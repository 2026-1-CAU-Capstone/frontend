Initial Finding

RAG가 모든 측정 축에서 성능을 떨어뜨렸다.

예측: RAG가 도메인 지식을 보강해 점수를 올린다. 실제: 구조분석 Roman 정확도가 17pt 하락, 이론 단답은 한 문항이 RAG 컨텍스트 때문에 정답을 뒤집힘, 설명 평균 점수는 0.50pt 하락. 심지어 +Rule+RAG < +Rule — 완벽한 룰 컨텍스트가 있어도 RAG 노이즈가 흠집을 낸다.

Followup · 원인 추적과 처방

"RAG가 망가진 게 아니라, 우리가 잘못 쓰고 있었다"

"RAG가 도울 줄 알았는데 왜 깎냐"는 의심에서 출발한 후속 작업. 두 가지 별개 문제를 찾아 고친 뒤 재측정.

CAUSE 01

인덱스가 신규 standards 20+곡을 누락

ChromaDB에는 285청크 · 21곡만 색인된 반면, 디스크엔 39개 standards 파일. 신규 파일들이 영문 헤더(**Title:**)를 쓰는데 chunker는 한국어 라벨(**곡명:**)만 인식 → song 메타데이터가 빈 문자열로 들어가 retrieval에서 곡명 매칭이 전혀 안 됐다.

285 → 498 chunks · 21 → 39 songs
CAUSE 02

약한 매치도 무조건 5개 주입

/search?n=5는 코사인 ~0.5 짜리 약한 매치도 그냥 내려준다. b17(backdoor) 질의는 top-5가 모두 0.71↓ 점수의 "CMaj7 등장하는 다른 곡 분석"이었는데 ctxBlock이 그대로 모델에 권위 있는 컨텍스트로 주입 → 모델은 충실히 따라가 오답 도출.

no score threshold · n=5

처방 1: chunker의 메타 정규식에 영문 라벨 alternation 추가 → re-chunk + re-embed로 인덱스 재구축 (498 chunks · 39 songs). 처방 2: retrieve에 RAG_MIN_SCORE 임계값 + RAG_N 노브 추가 — 약한 매치는 drop, 전부 약하면 빈 컨텍스트 (= Raw로 fallback).

b17(backdoor → Bb7)를 비롯한 RAG-깎임 항목들이 임계값 적용 후 모두 회복: 약한 매치가 drop되며 모델이 Raw 사전지식으로 fallback. RAG가 더 이상 net-negative가 아닌 안전한 no-op이 된다 (도움 안 줄 땐 깎지도 않음). 한 항목(b28, F장조 V7 트라이톤 sub)은 rebuilt 인덱스의 새 청크가 정답을 끌어줬다가 filter에 의해 drop되며 잃음 — threshold가 너무 보수적일 때의 트레이드오프.

Final Verdict

RAG는 망가지지 않았다. 코퍼스·임계값·sourceType을 맞추면 룰 레이어를 능가한다.

세 번의 실험을 거쳐 결론: 운영 결함 셋 (인덱스 누락 → 약한 매치 무차별 주입 → 도메인 미스매치)을 차례로 고치자 +Rule+RAG가 +Rule 단독을 능가 (key 96 → 100%), +RAG 단독으로 ii-V-I F1 +6pt, Recall 100%, B/C 무해 (= Raw). 원래 "RAG가 깎는다"는 가설은 "이 코퍼스를 그 질문에 그렇게 주입하면 안 된다"였고, 제대로 주입하니 RAG가 명백한 net positive.

이 데이터가 말하는 것

01

룰 레이어 = 정량적 승자

Raw가 ii-V-I을 과잉검출(P 80%)한다. +Rule이 F1을 100%로, Roman을 99.2%로, key를 95.8%로 끌어올린다. Jazzify 룰 엔진의 존재이유가 숫자로 입증된다.

F1 87 → 100 · Roman 83 → 99
02

RAG는 살릴 수 있다 (조건부)

첫 결과만 보면 RAG가 모든 축을 깎았지만, 두 가지 운영 결함(인덱스 누락 + 약한 매치 무차별 주입)을 고치니 코퍼스가 답을 가진 영역(E)에선 +10pt, 추상 이론(B)에선 무해. "검색만 끼우면 좋아진다"는 거짓이지만 "RAG는 안 된다"도 거짓.

E +10pt · B fix +6.6pt
03

최종: +Rule+RAG > +Rule

처음엔 +Rule+RAG < +Rule이었지만, 태스크별 minScore + sourceType 튜닝 후 +Rule+RAG가 key 100% / F1 100% / Roman 99.2%로 +Rule(95.8/100/99.2)을 능가. RAG가 룰이 놓친 단 1문항(key)을 메웠다.
