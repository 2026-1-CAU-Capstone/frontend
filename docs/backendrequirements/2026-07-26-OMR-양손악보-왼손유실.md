### 기능 요약 (남은 범위 = 프론트 연결)
상세 응답의 `omrResult.pages[].musicXml`(+ `chordAssignmentsJson`)을 프론트에서 파싱해
양손(`bassMeasures`)·화음·코드를 복원하고 그랜드 스태프로 렌더한다.

### 상황 설명 (2026-07-29 실측 — 문서 기술이 코드와 어긋남)
기존 문서는 프론트가 "준비 완료"라 적었으나 실제 레포와 다르다:

1. 문서가 **"구현·검증 완료"** 로 적은 `frontend/src/lib/note/omrResultToSheet.ts` 가 **레포에 존재하지 않는다.**
2. `frontend/src` 전체에서 `omrResult` 를 **소비하는 코드가 0건**이다(주석 1건뿐 — `xmlMelodyParser.ts:1297`).
3. `frontend/src/api/schema.d.ts` 에 `omrResult` **0건** → `npm run api:types` 가 재실행되지 않았다.

실제로 준비된 것은 파서·렌더러뿐이다:
- `frontend/src/lib/note/xmlMelodyParser.ts` — `<staves>2` 자동 감지 + `parseGrandStaff`
  (양손 분리·화음 보존·`<harmony>` 코드) 구현·실데이터 검증 완료.
- `frontend/src/components/notesheet/NoteSheet.tsx` — 양손(그랜드 스태프) 렌더 지원 완료.

### 기능 상세
- **사용자**: 로그인 사용자(OMR 업로드 — 솔로/릭/컴핑 수집)
- **권한**: 로그인
- **시나리오**: 양손 악보 업로드 → OMR 완료 → 상세 응답의 `omrResult` 를 프론트가 파싱 → 양손으로 표시
- **동작 조건**
  1. `npm run api:types` 재실행해 `schema.d.ts` 에 `omrResult` 타입을 반영한다.
  2. `omrResult.pages[].musicXml` + `chordAssignmentsJson` → `NoteSheetData` 변환 모듈을
     **새로 구현**한다(멀티페이지 병합 포함). 파싱 자체는 기존 `parseGrandStaff` 를 재사용.
  3. 솔로 상세/에디터 로드 시 `omrResult` 가 있으면 그 결과로 악보를 구성하고,
     없으면 기존 `sheetData` 로 폴백한다(구 데이터 하위호환).
- **검증 조건**
  - 양손 PDF/이미지 OMR 후 상세 응답 `omrResult.pages[0].musicXml` 이 `<staves>2` 를 포함하고,
    프론트에서 그랜드 스태프(위 트레블/아래 베이스 + brace)로 렌더된다.
  - 기존 단선율 솔로는 회귀 없음.
