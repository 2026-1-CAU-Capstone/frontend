# 2026-07-26 · OMR 양손(그랜드 스태프) 왼손 유실 요구사항 1건

🏷 **범주(태그):** 음악 분석 파이프라인 / 미디어 추론
양손(피아노) 악보를 OMR 로 올려도 **화면에는 오른손만 나온다.** OMR 엔진은 양손을 인식하지만
백엔드가 `sheetData` 로 변환하며 왼손을 버리고, 프론트가 직접 복원할 원료(`omrResult` 원문)도
비어 있다. **프론트는 양손 렌더·파서가 이미 준비 완료** — 원료만 내려주면 즉시 켜진다.

## 진행 현황
범례: ✅ 완료 · 🟡 진행중 · ⬜ 미시작
- ⬜ 1. `omrResult.pages[].musicXml` 원문을 실제로 저장·응답 (권장 A안)

## 1. OMR 원문(musicXml) 노출 → 프론트가 양손 복원  ⬜ 미시작

### 기능 요약
OMR 완료 시 페이지별 **MusicXML 원문**을 `omrResult` 에 저장해 응답으로 내려준다(문서 #23 에
이미 정의된 계약). 프론트가 원문을 파싱해 양손(bassMeasures)·화음·코드까지 복원한다.

### 상황 설명 (2026-07-26 실측)
- `SheetDataResponse` 필드 = `key, measures, tempo, timeSignature, title` 뿐 — **왼손
  (`bassMeasures`)을 담을 그릇이 스펙 전체에 없다**(검색 0건). OMR 엔진(HOMR)이 MusicXML 에
  `<staves>2</staves>` 로 양손을 뽑아줘도 백엔드 변환에서 staff 1(오른손)만 남는다.
- `omrResult` 는 문서 #23 계약에 있으나 **실측 응답은 전부 `null`** (최근 candidate 솔로 포함).
  → 프론트가 자체 파싱으로 복원할 원료도 없다.
- 사용자 체감: 양손 악보를 넣었는데 결과가 한손으로 나옴(왼손 데이터 유실 — 재인식 불가).

### 프론트 준비 상태 (참고 — 원료만 오면 끝)
- `frontend/src/lib/note/xmlMelodyParser.ts` — `<staves>2` 자동 감지 + `parseGrandStaff`
  (양손 분리·화음 보존·`<harmony>` 코드) **구현·실데이터 검증 완료**.
- `frontend/src/lib/note/omrResultToSheet.ts` — `omrResult.pages[].musicXml` +
  `chordAssignmentsJson` → 완전한 양손 악보 변환 모듈 **구현·검증 완료**(멀티페이지 병합 포함).
- `frontend/src/components/notesheet/NoteSheet.tsx` — 양손(그랜드 스태프) 렌더 지원 완료.
- 즉 백엔드가 원문만 채워주면 **프론트 코드 수정 없이** 호출부 연결만으로 양손이 살아난다.

### 기능 상세
- **사용자**: 로그인 사용자(OMR 업로드 — 솔로/릭/컴핑 수집)
- **권한**: 로그인
- **시나리오**: 양손 악보 업로드 → OMR 완료 → 상세 응답의 `omrResult.pages[].musicXml` 에
  원문 포함 → 프론트가 파싱해 양손으로 표시
- **동작 조건**
  1. OMR 완료 시 페이지별 MusicXML 원문(+ `chordAssignmentsJson`)을 저장하고
     상세 응답(`GET /v1/solos/{id}` 등)의 `omrResult` 로 반환한다 — 문서 #23 계약 그대로.
  2. 기존 데이터는 원문이 없으므로 `null` 유지(신규 인식부터 적용).
  3. (대안 B안) `omrResult` 저장이 어려우면 `SheetDataResponse` 에 `bassMeasures`
     (measures 와 동일 스키마, staff 2)를 추가하는 방법도 있다 — 단 이 경우 화음·코드 보존
     파싱을 백엔드가 책임져야 하므로 A안(원문 노출)을 권장.
- **검증 조건**
  - 양손 PDF/이미지 OMR 후 상세 응답 `omrResult.pages[0].musicXml` 이 비어 있지 않고
    `<staves>2` 를 포함.
  - 프론트에서 해당 악보가 그랜드 스태프(위 트레블/아래 베이스 + brace)로 렌더.
- **기대 결과 및 완료 기준**
  - [ ] OMR 완료 건의 `omrResult.pages[].musicXml` 채워짐 (null 아님)
  - [ ] 양손 원본 → 프론트에서 양손으로 표시 (왼손 유실 없음)
  - [ ] `chordAssignmentsJson` 도 함께 채워짐 (코드 배정 복원용)
