# 2026-08-08 · 코드·악보 차트 폴더 정리 + 휴지통(소프트삭제) 2건

🏷 **범주(태그):** 콘텐츠·라이브러리·스토리지

사용자가 **내 코드 차트·내 악보 차트를 폴더로 정리**하고(폴더 추가·이름변경·삭제·중첩·차트 넣고 빼기), 삭제는 영구삭제 대신 **휴지통(소프트삭제·복구 가능)** 을 거치도록 한다. 두 기능은 삭제 동작에서 맞물린다(폴더 캐스케이드 삭제 → 휴지통행). 프론트에는 폴더 UX가 이미 목업(localStorage)으로 구현돼 있으나 서버 개념이 전무해 기기 간 동기화·서버 차트 소속이 안 된다.

## 진행 현황
범례: ✅ 완료 · 🟡 진행중 · ⬜ 미시작
- ⬜ 1. 코드·악보 차트 폴더 정리 (← BR-49) · **P1**
- ⬜ 2. 휴지통(소프트삭제 + 구조 보존 복구) (← BR-50) · **P1**

> **단계화(권장 착수 순서):** BR-49(폴더)를 먼저 살리되 그 삭제는 **캐스케이드 + 확인창**으로 시작하고, BR-50(휴지통)이 붙는 순간 그 삭제가 자동으로 **휴지통행(소프트삭제)** 으로 승격되게 한다. 둘 다 P1.
>
> **프론트 현황(참고):** [MyChordChartsPage] 에 폴더 추가·이름변경·삭제(하위 캐스케이드)·드래그 이동·중첩·브레드크럼이 **전부 구현**돼 있으나 `localStorage` 목업이다. 악보 페이지는 폴더 UI 자체가 없다(“이동: 추후 구현” 스텁). 서버 계약만 생기면 프론트는 저장소를 목업→서버로 바꾸고, 폴더 로직을 두 페이지 공용 훅으로 승격한다.

## 1. 코드·악보 차트 폴더 정리  ⬜ 미시작  (← BR-49) · P1

### 기능 요약
로그인 사용자가 자신의 코드 차트·악보 차트를 **폴더(중첩 가능)** 로 정리한다. 폴더 CRUD + 차트를 폴더에 넣기/빼기/이동. 폴더는 **코드용·악보용을 하나의 개념으로 공유하되 `kind` 로 논리 트리를 분리**한다.

### 상황 설명
- 백엔드에 폴더 개념이 전혀 없다: 폴더 엔드포인트 0개, `ChordProjectResponse`·`SheetProjectResponse` 에 `folderId`/`parentId` 필드 없음.
- 프론트 폴더 동작은 전부 `localStorage` 목업이라 (a) 기기·브라우저 간 동기화 안 됨, (b) 서버에 저장된 차트에 폴더 소속이 붙지 않음, (c) 악보 차트는 폴더 UI 자체가 없음.
- 내 코드 차트(노랑)와 내 악보 차트(초록)는 **서로 다른 라이브러리(별도 페이지·진입점)** 다. 한 폴더에 코드·악보가 섞이면 이 2-라이브러리 구조와 어긋난다 → 폴더에 `kind` 구분자가 필수.

### 기능 상세
- **사용자**: 일반 로그인 사용자
- **권한**: 로그인 필요. 본인 소유 폴더·차트만 조회·수정·삭제(소유자 스코프는 기존 chord/sheet-project 와 동일).
- **시나리오**:
  - 폴더 생성 → 이름 입력 → 현재 보고 있는 위치(`parentId`)에 폴더가 생성됨(루트면 `parentId=null`).
  - 차트를 폴더로 드래그 → 그 차트의 `folderId` 가 대상 폴더로 바뀜.
  - 폴더 안 차트를 루트(또는 상위)로 드래그 → `folderId=null`(또는 상위 폴더 id).
  - 폴더 이름 변경 / 폴더 자체를 다른 폴더로 이동(중첩) / 폴더 삭제(안의 하위 폴더·차트까지 캐스케이드).
- **동작 조건** (외부 API 계약 — `제안`):
  - **Folder 개념(신규)**: `publicId`(UUID) · `userId`(소유자) · `kind`(`CHORD` | `SHEET`) · `parentId`(nullable, **같은 `kind` 안에서만** 중첩) · `name` · `createdAt`/`updatedAt`.
  - **차트 소속 필드(추가)**: `chord_project.folderId`(nullable), `sheet_project.folderId`(nullable). 각 단건·목록 Response 에 `folderId` 노출(`null` = 루트).
  - **엔드포인트(제안)**:
    ```
    GET    /v1/folders?kind=CHORD|SHEET
      → 사용자의 해당 kind 폴더 전체를 플랫 리스트로(각자 parentId 포함).
        프론트가 parentId 로 트리를 구성한다. (삭제된 폴더 제외 = deletedAt IS NULL)
      응답 예: { data: [ { publicId, kind, parentId, name, createdAt, updatedAt } ] }

    POST   /v1/folders
      body: { name: string, kind: "CHORD"|"SHEET", parentId?: uuid|null }
      → 생성된 Folder 반환. parentId 는 같은 kind·본인 소유여야 함.

    PUT    /v1/folders/{publicId}
      body: { name?: string, parentId?: uuid|null }   // 이름변경 + 폴더 이동
      → 이동 시 사이클 금지: 자기 자신/자손으로 이동 요청은 400.

    DELETE /v1/folders/{publicId}
      → 폴더 + 하위 폴더 + 포함 차트까지 캐스케이드 삭제.
        (BR-50 적용 후에는 하드삭제가 아니라 소프트삭제 = 휴지통행으로 승격)

    // 차트를 폴더에 넣기/빼기/이동 — 기존 PUT 확장
    PUT    /v1/chord-projects/{publicId}   body: { folderId?: uuid|null }
    PUT    /v1/sheet-projects/{publicId}   body: { folderId?: uuid|null }
      ※ 악보 PUT 은 현재 title·key 만 받으므로 folderId 를 받도록 확장 필요.
      ※ folderId 는 본인 소유 & kind 일치(코드 차트→CHORD 폴더)여야 함.

    // 폴더별 목록 필터(스케일 대비, 서버 필터 제안)
    GET    /v1/chord-projects?folderId={uuid|null|생략}
    GET    /v1/sheet-projects?folderId={uuid|null|생략}
      → folderId 생략 시 기존과 동일(전체). null 이면 루트 소속만.
    ```
  - **검증(거부 케이스)**: 남의 폴더/차트 접근 → 403 또는 404. `parentId` 사이클 → 400. `kind` 불일치(코드 차트를 `SHEET` 폴더로) → 400. 존재하지 않는 `folderId` → 400/404.
- **검증 조건**:
  - 폴더 생성·이동·이름변경·삭제 후 `GET /v1/folders` 결과에 반영된다.
  - 차트 `folderId` 변경 후 `GET /v1/{chord|sheet}-projects?folderId=` 결과가 정확히 갈린다.
  - 다른 기기로 로그인해도 동일 폴더 트리·소속이 보인다(서버가 단일 진실원천).
  - 사이클/kind 불일치/타인 리소스 요청이 규정된 상태코드로 거부된다.
- **기대 결과 및 완료 기준**:
  - [ ] `Folder`(kind·parentId·소유자) 개념 + `chord/sheet_project.folderId` 필드 도입, 각 Response 에 `folderId` 노출.
  - [ ] 폴더 `GET/POST/PUT/DELETE` 엔드포인트 제공(사이클·kind·소유자 검증 포함).
  - [ ] 차트 이동(`PUT …/{id} { folderId }`) — 코드·악보 양쪽. 악보 PUT 에 folderId 추가.
  - [ ] 폴더별 목록 필터(`?folderId=`) — 코드·악보 양쪽.
  - [ ] 폴더 삭제가 하위·포함 차트까지 캐스케이드(BR-50 전에는 하드, 후에는 소프트).

## 2. 휴지통 — 소프트 삭제 + 구조 보존 복구  ⬜ 미시작  (← BR-50) · P1

### 기능 요약
코드·악보 차트와 폴더의 삭제를 **영구삭제 대신 휴지통(소프트삭제)** 으로 바꾼다. 휴지통은 **원래 폴더 구조를 보존해 탐색**할 수 있고(지운 폴더는 폴더로 남아 클릭해 들어감), **개별 항목을 원래 경로로 복구**한다. 30일 경과분은 자동 영구삭제.

### 상황 설명
- 현재 `DELETE /v1/chord-projects/{id}` · `/v1/sheet-projects/{id}` 는 **영구 하드삭제(204, 복구 불가)** 다. 휴지통이 없다.
- BR-49의 폴더 캐스케이드 삭제와 결합하면 **실수 한 번에 폴더 + 안의 차트 전부가 영구 소실**된다. Google Drive·Apple 노트 등 대부분의 서비스가 “폴더 삭제 시 내용까지 삭제하되 **휴지통으로**(30일 복구)” 를 안전망으로 둔다 — 지금은 그 안전망이 없다.

### 기능 상세
- **사용자**: 일반 로그인 사용자
- **권한**: 로그인 필요. 본인 휴지통만.
- **시나리오**:
  - 차트/폴더 삭제 → 목록에서 즉시 사라지되 **휴지통으로 이동**(영구삭제 아님). 확인창 문구는 “휴지통으로 이동됩니다(30일 후 자동 삭제)”.
  - 휴지통 열기 → 삭제된 항목이 **원래 폴더 구조 그대로** 보임. 지운 폴더는 폴더로 남아 있고 **클릭해 그 안으로 들어갈 수 있다**.
  - 예) 폴더 안의 코드 프로젝트 A만 복구: 휴지통에서 `폴더 → …(경로) → A` 로 들어가, A 에 우클릭/⋯ **복구** → **A 가 원래 자리로 복구**된다. A 의 조상 폴더 체인이 아직 삭제 상태면 **함께 되살아나 경로가 복원**된다. 형제 항목들은 휴지통에 그대로 남는다.
  - 폴더 복구: 폴더를 복구하면 그 **폴더 + 조상 체인 + 휴지통에 있는 그 하위 전체**가 복구된다.
  - 휴지통에서 항목별 **영구 삭제**(우클릭/⋯).
  - 삭제 후 **30일 경과분은 자동 영구삭제**.
- **동작 조건** (외부 API 계약 — `제안`):
  - **소프트삭제 필드(추가)**: `chord_project` · `sheet_project` · `folder` 에 `deletedAt`(nullable timestamp) + `deleteBatchId`(같은 삭제 작업 묶음 식별자) 추가.
  - **기존 목록·조회는 전부 `deletedAt IS NULL` 만** 반환(삭제된 것 숨김). 폴더 목록(`GET /v1/folders`)도 동일.
  - **DELETE 전환**: `DELETE /v1/chord-projects/{id}` · `/v1/sheet-projects/{id}` · `/v1/folders/{id}` → 하드삭제 대신 **소프트삭제**. 폴더 삭제는 **하위 폴더 + 포함 차트까지 같은 `deleteBatchId` 로 한 번에** 소프트삭제(원래 `parentId`/`folderId` 는 보존해 구조를 남긴다).
  - **휴지통 API(탐색형)**:
    ```
    GET  /v1/trash?kind=CHORD|SHEET&parentId={uuid|생략}
      → parentId 생략 = 휴지통 "루트": 삭제의 최상위 항목만
         (= deletedAt IS NOT NULL 이면서, 그 부모가 삭제되지 않았거나 없는 항목).
      → parentId=<폴더> = 그 (삭제된) 폴더 안의 삭제된 항목들.
        이렇게 라이브러리와 똑같이 parentId 로 파고들며 탐색한다.
      응답: 폴더 + 차트가 섞인 목록(각자 type·publicId·parentId·name/title·deletedAt).

    POST /v1/trash/restore
      body: { kind, type: "folder"|"chart", publicId }
      → 복구. type=chart: 그 차트 deletedAt 해제 + 조상 폴더 체인 중
        아직 삭제 상태인 것들도 deletedAt 해제(경로 복원). 형제는 유지.
        type=folder: 그 폴더 + 조상 체인 + 그 하위(휴지통 내) 전체 복구.

    DELETE /v1/trash
      body: { kind, type, publicId }
      → 영구 삭제. type=folder 면 그 하위 subtree 도 영구 삭제.
    ```
  - **보존 정책**: `deletedAt` 이 30일 지난 항목을 **스케줄 잡으로 자동 영구삭제**(폴더면 subtree 포함). TTL 은 설정값으로.
- **검증 조건**:
  - 차트·폴더 삭제 → 일반 목록에서 사라지고 휴지통에 나타난다(영구삭제 아님).
  - 휴지통을 `parentId` 로 파고들어 삭제된 폴더 안의 항목(A)까지 도달한다.
  - A 개별 복구 시 A 가 **원래 폴더 경로**로 돌아오고(조상 폴더 함께 부활), 형제는 휴지통에 남는다.
  - 폴더 복구 시 하위 전체가 함께 복구된다.
  - 영구삭제·30일 자동삭제가 동작한다(테스트는 짧은 TTL 로 판정).
- **기대 결과 및 완료 기준**:
  - [ ] `deletedAt` + `deleteBatchId` 도입, 모든 기존 목록·조회가 `deletedAt IS NULL` 만.
  - [ ] 코드·악보·폴더 DELETE 가 소프트삭제로 전환(폴더는 캐스케이드 batch).
  - [ ] 탐색형 휴지통 목록 `GET /v1/trash?kind=&parentId=`.
  - [ ] 복구 `POST /v1/trash/restore` — 차트 개별 복구 시 조상 경로 복원, 폴더 복구 시 subtree 복원.
  - [ ] 영구삭제 `DELETE /v1/trash` + 30일 자동 purge 스케줄 잡.
