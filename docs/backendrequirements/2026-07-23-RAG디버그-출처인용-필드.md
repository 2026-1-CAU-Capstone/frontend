# 2026-07-23 · RAG 디버그 블록 출처·인용 필드 보강 요구사항 2건

🏷 **범주(태그):** RAG·화성 검색(HarmoRAG)
프론트 채팅 UI(출처 인용·RAG 디버그 패널)는 이미 만들어져 있으나, 백엔드가 `RAG_DEBUG` 블록에
**출처 종류(`source_type`)와 실행 상태(`status`)**를 안 실어줘서 인용/오프라인 표시가 동작하지 않는다.
프론트 코드 수정 없이 **백엔드가 debug 필드만 채우면** 바로 켜진다.

## 진행 현황
범례: ✅ 완료 · 🟡 진행중 · ⬜ 미시작
- ⬜ 1. 청크 debug 에 `source_type` 추가 (이미 색인돼 있음 → 매핑만) + YouTube 출처 필드
- ⬜ 2. `RAG_DEBUG` 에 `status`(connected/offline) 추가

- `frontend/src/api/harmorag.ts` — `RagChunk` / `RagDebugInfo` 인터페이스. **이 필드 이름·형태가 계약이다.**
- `frontend/src/components/chat/RagDebugPanel.tsx` — `status==='offline'` 이면 패널을 접고 빨간색 처리. `video_id`/`video_url`/`channel`/`start_sec` 로 영상 인용 렌더.
- `frontend/src/components/chat/ChatMessage.tsx` — 답변 각주 `[n]` → `ragDebug.chunks[n-1]` 로 인용. `source_type==='youtube'` 면 `video_url`(+`start_sec`) 딥링크.

**백엔드 현재 구현(여기를 고치면 된다)**
- `backend/src/main/java/com/jazzify/backend/domain/rag/service/implementation/RagAgent.java` — `RAG_DEBUG` 의 `chunks[]`·상위 필드를 만드는 곳(`buildChunkDebug`, L155~163). **여기서 `source_type` 등을 안 넣고 있다.**
- `backend/.../rag/service/implementation/RagChatStreamer.java` — debug 블록을 스트림에 쓰는 곳(L101~115). 정상 실행 시 `status` 를 안 넣고, 예외 시에만 `error` 를 넣는다.
- `backend/.../rag/model/RagChunkSearchResult.java` — 검색 결과 레코드. **`sourceType` 이미 보유**(색인 메타 `RagVectorStoreRepository` L127 에서 저장).

## 1. 청크 debug 에 출처 필드 추가  ⬜ 미시작

### 기능 요약
`RAG_DEBUG.chunks[]` 각 항목에 **`source_type`**(필수)과 **YouTube 출처 필드**(있을 때)를 추가해,
프론트가 텍스트 출처/영상 출처를 구분하고 각주를 영상 딥링크로 렌더할 수 있게 한다.

### 상황 설명
프론트는 답변의 각주 `[1]` 을 누르면 출처로 이동하도록 이미 구현돼 있다. `source_type` 이 `'youtube'` 면
`video_url`(+`start_sec`) 로 **영상의 정확한 시점** 딥링크, `'standard'`/`'lesson'` 이면 텍스트 출처로 표시한다.
그런데 백엔드 `buildChunkDebug`(`RagAgent.java` L155~163)가 넣는 필드는
`id·score·rrf_score·title·song·level·matched_query·matched_queries·response` 뿐이라 **`source_type` 이 아예 없다.**
→ 프론트에서 출처 종류를 알 수 없어 인용 UI 가 텍스트/영상 구분 없이 반쯤 죽어 있다.

`source_type` 은 **이미 색인돼 있다**: `RagVectorStoreRepository`(L127)가 메타에 `sourceType` 을 저장하고,
검색 결과 `RagChunkSearchResult`(L12)도 `sourceType` 을 들고 있다. **debug 맵에 꺼내 넣기만** 하면 된다.

YouTube 필드는 사정이 다르다(아래 데이터 확인 참고).

### 데이터 현황 (중요 — 구현 범위가 갈린다)
`backend/data/explanation/` 원본 기준:
- **standards 20개**: `강의 출처:` **텍스트만**. YouTube 링크 없음 → `source_type: "standard"` 만 채우면 된다.
- **lessons 2개**: 파일 상단에 `url : https://youtu.be/…` **영상 URL 있음**. 단 **청크별 타임스탬프(start_sec)는 없음**(영상 단위 URL 하나뿐).

따라서:
- `source_type` + (lesson 의) `video_url`·`video_id`·`channel` 은 **지금 데이터로 채울 수 있다.**
- `start_sec`·`end_sec`(구절 시작 시점)은 **원본에 없다** → 지금은 생략(null). 추후 코퍼스에 타임스탬프가 들어오면 그때 채운다.

### 기능 상세
- **사용자**: 로그인 사용자(채팅 답변의 출처 인용)
- **권한**: 로그인
- **시나리오**: RAG 답변 수신 → 각주 `[n]` 표시 → 클릭 시 텍스트 출처 또는 영상 딥링크로 이동
- **동작 조건**: `RAG_DEBUG.chunks[]` 각 항목에 아래를 추가. 필드명은 프론트 `RagChunk`(스네이크 케이스) 그대로.
  ```jsonc
  {
    "id": "...", "score": 0.59, "rrf_score": 0.016,
    "title": "...", "song": "...", "level": 3,
    "matched_query": "...", "matched_queries": ["..."],
    "response": "...",
    "source_type": "standard",          // ★ 필수. standard | lesson | youtube
    // ↓ lesson/youtube 이고 데이터에 있을 때만 (standard 는 생략/누락 허용)
    "video_id": "iNgtPSlhe6A",           // youtu.be/<id> 에서 파싱
    "video_url": "https://youtu.be/iNgtPSlhe6A",
    "channel": "Bruce Harris",           // 있으면
    "start_sec": null                    // 데이터에 없으면 null/생략
  }
  ```
  - `source_type` 은 `RagChunkSearchResult.sourceType()` 을 debug 맵에 넣으면 된다(신규 색인 불필요).
  - lesson 의 `video_url`/`video_id` 는 원본 상단 `url :` 를 색인 메타에 넣고(현재 `RagVectorStoreRepository`
    메타에 없음) 검색 결과까지 실어와 debug 에 넣는다. (이 부분만 색인 메타 확장이 필요)
- **검증 조건**
  - standard 청크: `source_type: "standard"`, 영상 필드 없음.
  - lesson 청크: `source_type: "lesson"`, `video_url`/`video_id` 채워짐.
  - 프론트에서 각주 클릭 시 lesson 은 영상으로, standard 는 텍스트 출처로 렌더.
- **기대 결과 및 완료 기준**
  - [ ] `chunks[].source_type` 항상 포함
  - [ ] lesson 청크에 `video_url`·`video_id`(+가능하면 `channel`) 포함
  - [ ] `start_sec` 는 데이터 없으면 null (추후 확장 여지만 남김)
  - [ ] 프론트 인용 UI(텍스트/영상 구분)가 동작

## 2. `RAG_DEBUG` 에 `status`(connected/offline) 추가  ⬜ 미시작

### 기능 요약
`RAG_DEBUG` 최상위에 이번 턴 RAG 실제 동작 여부를 나타내는 **`status`**(`"connected"`/`"offline"`)를 추가한다.

### 상황 설명
프론트 `RagDebugPanel`(L249)은 `info.status === 'offline'` 이면 패널을 **빨간색으로 접어** "이 답변은 RAG 없이
나왔다"를 사용자에게 알린다. 그런데 백엔드는 정상 실행 시 `status` 를 안 넣고(`RagAgent` L37~42),
예외 시에만 `error` 를 넣는다(`RagChatStreamer` L112). → `status` 가 늘 `undefined` 라 오프라인 표시가 안 뜬다.

이는 문서 #18 의 RAG health 오탐과 같은 결의 문제다(실패를 실패로 안 보여줌).

### 기능 상세
- **사용자**: 로그인 사용자(RAG 디버그 패널)
- **권한**: 로그인
- **시나리오**: RAG 정상 동작 턴 → `status: "connected"` / 임베딩·검색 실패 턴 → `status: "offline"`(+`error`)
- **동작 조건**
  - 정상 컨텍스트 빌드 성공 시 `debug.put("status", "connected")` (`RagAgent`).
  - 컨텍스트 빌드 실패(임베딩/검색 오류)로 `error` 를 넣는 경로(`RagChatStreamer` L111~112)에서
    `status: "offline"` 도 함께 넣는다.
- **검증 조건**
  - 정상 턴 응답의 `RAG_DEBUG.status === "connected"`.
  - 임베딩 서버를 의도적으로 죽인 뒤: `status === "offline"` + `error` 존재 → 프론트 패널이 빨간색·접힘.
- **기대 결과 및 완료 기준**
  - [ ] 정상 턴 `status: "connected"`
  - [ ] 실패 턴 `status: "offline"` (+ `error`)
  - [ ] 프론트 RagDebugPanel 이 오프라인 상태를 시각적으로 구분
