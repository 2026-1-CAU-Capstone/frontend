## 1. 익명·폴백 채팅 프록시 + 키 회전  ⬜ 미시작  (← BR-5) [최우선·보안]

### 기능 요약
비로그인/폴백 채팅이 브라우저에서 Anthropic을 **직접** 부르지 않도록 서버 프록시를 만들고, 노출된 API 키를 폐기·재발급한다.

### 상황 설명
프론트가 비로그인·백엔드 장애 폴백 시 `VITE_ANTHROPIC_API_KEY`로 Anthropic을 직접 호출한다. `VITE_` 변수는 빌드 시 JS 번들에 그대로 박혀 **배포 사이트/IPA에서 키가 노출**된다. 누구나 우리 계정으로 무제한 호출 가능(요금은 우리 부담), 키를 지워도 이미 배포된 번들의 키는 계속 유효.

### 기능 상세
- **사용자**: 비로그인 방문자(익명), 로그인 사용자(폴백)
- **권한**: 익명 허용 (단 rate limit 필수)
- **시나리오**: 익명 사용자가 채팅 → 프론트가 서버 익명 프록시 호출 → 서버가 Anthropic 대리 호출 → 스트림 반환
- **동작 조건**
  1. 기존 Anthropic 키 **즉시 폐기(revoke) 후 재발급** (코드 수정보다 먼저, 유출 가정). RAG 접근 토큰도 폐기·재발급 후 서버 보관.
  2. 익명용 프록시. `제안`:
     ```jsonc
     POST /v1/chat/public/stream   // 인증 불필요
     { "message": "...", "history": [...], "useRag": false }
     → text/plain 스트림 (로그인 채팅과 동일 포맷)
     ```
  3. 남용 방지(없으면 새 과금 구멍): IP+세션 **rate limit**(예 분당 5·일 30), 요청당 `max_tokens` 상한, 폭주/봇 차단, 익명 이력 미저장(또는 짧은 TTL).
- **검증 조건**: 익명 프록시 초과 요청 시 **429**. 프론트에서 `api.anthropic.com` 직접 호출 제거해도 모든 채팅 동작.
- **기대 결과 및 완료 기준**
  - [ ] 기존 키 콘솔에서 revoke
  - [ ] 새 키는 **서버에만** 존재(.env·프론트·번들 어디에도 없음)
  - [ ] 익명 프록시 rate limit 동작(초과 429)

## 2. 긴 답변 중간 끊김  ⬜ 미시작  (← BR-1)

### 기능 요약
긴 답변이 문장 중간에서 잘리지 않고 끝까지 도착하게 한다.

### 상황 설명
화성 분석 등 긴 답변 요청 시 답이 문장 도중 끊긴다(예: *"E-7은 다이아토닉 iii,"* 에서 종료). AI 코드 차트는 보통 답변 뒤쪽에 오므로, 끊기면 **"차트가 안 나온다"** 는 별개 버그처럼 보인다. 프론트 파서/폴백(max 16384)은 정상 확인 → **백엔드 스트림 경로에서 발생**(토큰 한도 또는 프록시 타임아웃 의심).

### 기능 상세
- **사용자**: 로그인 사용자
- **권한**: 로그인
- **시나리오**: 긴 화성 분석 질문 → 3,000자+ 답변과 뒤쪽 차트 블록까지 스트림 수신
- **동작 조건**: 스트림 응답 토큰 상한을 충분히(최소 8192, 가능하면 16384), 스트리밍 프록시 타임아웃을 답변 생성 시간 이상으로. (내부 설정값은 백엔드 재량 — 결과 기준으로만 판정)
- **검증 조건**: 60초+ 응답도 중간 연결 끊김 없음.
- **기대 결과 및 완료 기준**
  - [ ] 3,000자 이상 답변 + 뒤쪽 차트 블록이 **끝까지** 도착
  - [ ] 60초 이상 응답도 연결 유지

## 4. 메시지 편집·재생성 이력 정합(fork)  ⬜ 미시작  (← BR-8)

### 기능 요약
메시지 편집/재생성 시 서버 히스토리가 화면과 정확히 일치하도록 한다.

### 상황 설명
편집/재생성 시 프론트는 그 지점 이후를 잘라 새로 잇는다(fork). 그런데 백엔드 히스토리는 append-only라, 새로고침하면 **지운 턴이 부활**하고 재생성 턴이 **중복**으로 남는다.

### 기능 상세
- **사용자**: 로그인 사용자
- **권한**: 본인 채팅
- **시나리오**: 메시지 편집/재생성 → 새로고침 → 화면과 서버 이력 동일
- **동작 조건**: 메시지 단위 수정/삭제 API **또는** "이 메시지 이후 히스토리를 이걸로 대체"하는 fork/branch 엔드포인트 중 하나. (방식은 백엔드 재량)
- **검증 조건**: 편집·재생성 후 새로고침해도 부활/중복 없음.
- **기대 결과 및 완료 기준**
  - [ ] 편집·재생성 후 화면 = 서버 이력 정확히 일치

## 5. 채팅 제목 내부 프롬프트 제거  ⬜ 미시작  (← BR-19)

### 기능 요약
자동 생성 제목·이력에서 내부 지시문(`[내부 지시 …]`)을 서버에서도 제거한다.

### 상황 설명
백엔드가 첫 사용자 메시지로 제목을 자동 생성하는데, 과거 프론트가 릭 주입용 증강 프롬프트(`[내부 지시 — 유저에게 보이지 않음: …]`)를 사용자 메시지에 붙여 보내, 그 블록이 **제목·이력에 그대로 저장**됐다. 사이드바 제목에 내부 지시문이 노출될 수 있다.

### 기능 상세
- **사용자**: 로그인 사용자
- **권한**: —
- **시나리오**: 채팅 생성 → 제목 자동 생성 시 내부 지시 블록 제외
- **동작 조건**: (1) 제목 자동 생성 시 `[내부 지시` 이후를 서버에서 잘라낸다. (2) 기존 DB 레코드(제목·메시지)를 일괄 정제하는 마이그레이션.
- **검증 조건**: 신규/기존 채팅 제목에 `[내부 지시` 문자열이 없음.
- **기대 결과 및 완료 기준**
  - [ ] 신규 제목에 내부 지시 미포함
  - [ ] 기존 레코드 정제 완료

> 프론트는 표시 직전 `stripInternalInstructions()`로 가리는 방어를 유지 중(DB 잔존 레코드 대비).
