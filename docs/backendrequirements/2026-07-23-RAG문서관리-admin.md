# 2026-07-23 · RAG 문서 관리(admin) 백엔드 보강 요구사항 3건

🏷 **범주(태그):** RAG·화성 검색(HarmoRAG)
프론트에 **admin 전용 "RAG 문서 관리" 화면**(`/admin/rag`)을 만든다. 문서 목록(분류별)·상세(원본 전사문·메타·섹션)
열람 + 직접 추가/수정/삭제. 문서 CRUD API(`/v1/rag/documents`)는 **이미 존재**하므로, 아래 3가지만 보강하면
프론트가 바로 붙는다. (신규 CRUD 설계 불필요 — 기존 것 재사용)

## 1. RAG 문서 API 를 admin 전용으로 게이팅  ⬜ 미시작

### 기능 요약
`/v1/rag/documents` 계열(목록·상세·생성·수정·삭제)을 **ADMIN/MANAGE 권한**으로 제한한다.

### 상황 설명
현재 `SecurityConfig` 는 `/v1/rag/health` 만 `permitAll` 이고 나머지 RAG 문서 API 는 "인증만 되면 누구나"
접근 가능하다(`RagController` 에 `@PreAuthorize` 없음). RAG 문서 관리는 admin 기능이므로, **일반 유저가 문서를
추가·삭제할 수 있는 지금 상태는 위험**하다. 프로젝트에는 이미 동일 목적의 패턴이 있다:
`SecurityConfig` L55~59 의 licks/solos 쓰기 = `hasAnyRole("ADMIN","MANAGE")`.

### 기능 상세
- **사용자**: 관리자(ADMIN/MANAGE)
- **권한**: ADMIN 또는 MANAGE
- **시나리오**: admin 이 `/admin/rag` 에서 문서를 열람·추가·수정·삭제 / 일반 유저는 403
- **동작 조건**: `SecurityConfig` 에 아래를 추가(licks/solos 와 동일 방식). `search`·`health` 는 제외.
  ```
  .requestMatchers(HttpMethod.POST,   "/v1/rag/documents/**").hasAnyRole("ADMIN","MANAGE")
  .requestMatchers(HttpMethod.PUT,    "/v1/rag/documents/**").hasAnyRole("ADMIN","MANAGE")
  .requestMatchers(HttpMethod.DELETE, "/v1/rag/documents/**").hasAnyRole("ADMIN","MANAGE")
  .requestMatchers(HttpMethod.GET,    "/v1/rag/documents/**").hasAnyRole("ADMIN","MANAGE")
  ```
  - `GET /v1/rag/search` 는 채팅 RAG 가 쓰므로 **게이팅하지 않는다**(일반 인증 유지).
  - `GET /v1/rag/health` 는 기존대로 `permitAll`.
- **검증 조건**: admin 토큰 → 200 / 일반 유저 토큰 → 403 / 비로그인 → 401.
- **기대 결과 및 완료 기준**
  - [ ] 문서 목록·상세·생성·수정·삭제가 ADMIN/MANAGE 에서만 200
  - [ ] 일반 유저는 403, `/rag/search`·`/rag/health` 는 영향 없음

## 2. 문서별 청크(섹션) 나열 API 신규  ⬜ 미시작

### 기능 요약
문서 하나가 색인되며 쪼개진 **청크(섹션) 목록**을 조회하는 API 를 추가한다.
관리 화면에서 "이 문서가 실제로 어떤 섹션들로 저장됐는지"를 보여주는 데 쓴다.

### 상황 설명
문서 상세(`GET /v1/rag/documents/{id}`)는 `content`(원본 전사문 통짜)와 `chunkCount`(숫자)만 준다.
실제 벡터스토어에 저장된 **개별 청크(섹션 단위)** 를 나열하는 엔드포인트가 없다. 청크 메타에는 이미
`sectionId·level·title·instruction·response·topicTags·source` 가 저장돼 있어(`RagVectorStoreRepository`
L125~137) 신규 색인 없이 반환 가능하다. (검색용 `RagChunkResponse` 는 rrfScore/matchedQueries 등 검색
문맥 필드라 목적이 다르다 → 관리용 응답을 별도로 두는 편이 깔끔하다.)

### 기능 상세
- **사용자**: 관리자
- **권한**: ADMIN/MANAGE (항목 1과 동일 게이팅)
- **시나리오**: 문서 상세 열람 → 그 문서의 청크가 섹션 순서(`sectionId`)대로 나열됨
- **동작 조건**: `제안` — 새 엔드포인트 + 응답 스키마
  ```jsonc
  GET /v1/rag/documents/{publicId}/chunks
  → 200
  {
    "data": [
      {
        "chunkId": "standard__cherokee__1-1",
        "sectionId": "1-1",
        "level": 1,
        "title": "재즈 스탠더드 분석의 출발점",
        "instruction": "...",   // 있으면
        "response": "...",       // 청크 본문
        "topicTags": ["1625", "dim7"],
        "source": "태인재즈맨"
      }
    ]
  }
  ```
  - 정렬: `sectionId`(또는 색인 순서) 오름차순.
  - 페이징은 선택 — 한 문서당 청크가 수십 개 수준이라 전량 반환도 무방(구현 편의에 맡김).
- **검증 조건**: 특정 문서의 청크 수가 해당 문서 `chunkCount` 와 일치. 섹션 순서가 원본과 동일.
- **기대 결과 및 완료 기준**
  - [ ] `GET /v1/rag/documents/{id}/chunks` 가 섹션 단위 청크 배열 반환
  - [ ] 각 청크에 `sectionId·level·title·response·topicTags` 포함
  - [ ] 청크 수 = 문서의 `chunkCount`

## 3. 원본 링크(url) 노출  ⬜ 미시작

### 기능 요약
lesson 문서의 **원본 YouTube URL** 을 문서 응답(또는 청크 응답)에 노출한다.

### 상황 설명
관리 화면에서 "원본 링크"를 열람/복사할 수 있어야 한다. lesson 원본 txt 상단에 `url : https://youtu.be/…`
가 있으나(standards 20개는 링크 없음), 현재 색인 메타(`RagVectorStoreRepository`)에 `url` 이 저장되지 않아
API 로 내려오지 않는다. 이는 **문서 #24(RAG 디버그 출처 필드)의 YouTube URL 이슈와 동일 원천**이므로 함께
처리하면 좋다.

### 기능 상세
- **사용자**: 관리자
- **권한**: ADMIN/MANAGE
- **시나리오**: 문서 상세 → 원본 링크 표시(있으면) → 클릭/복사
- **동작 조건**
  - 색인 시 lesson 원본의 `url` 을 청크 메타(및 문서 메타)에 저장 → **lesson 문서는 재색인 필요**.
  - 문서 응답의 `metadata` 맵에 `url` 을 실어 보내면 스키마 변경 없이 노출 가능
    (또는 `RagDocumentResponse` 에 `sourceUrl` 필드 추가 — 택1, 백엔드 편의에 맡김).
  - standards 처럼 링크 없는 문서는 `url` 누락/`null`.
- **검증 조건**: lesson 문서 응답에 원본 URL 포함, standard 문서엔 없음.
- **기대 결과 및 완료 기준**
  - [ ] lesson 문서/청크 응답에 원본 URL 노출
  - [ ] 링크 없는 문서는 null/누락 (에러 아님)

> 문서 #24 와 관계: #24 는 "채팅 답변의 출처 인용"용 debug 필드, 본 항목은 "관리 화면의 원본 링크 열람"용.
> 둘 다 색인 메타에 `url` 을 넣는 같은 작업에서 파생되므로, url 색인은 한 번만 하면 양쪽이 해결된다.
