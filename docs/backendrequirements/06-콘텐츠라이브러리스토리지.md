## 1. 공유 링크 토큰 엔드포인트  ⬜ 미시작  (← BR-2)

### 기능 요약
코드차트·악보를 짧은 토큰 링크로 공유(발급/조회/폐기)하고, 받은 악보를 복제하는 경로.

### 상황 설명
현재 공유는 차트 전체를 URL 해시에 통째 인코딩하는 프론트 전용 v1(`/v?d=<base64url>`)이다. 문제: 차트가 크면 URL 폭증(메신저가 링크 자름), 원본 수정이 링크에 반영 안 됨(스냅샷), 조회수·만료·폐기 불가, 악보는 보기 전용이라 "내 것으로 복제"할 백엔드 경로가 없음. (🔴 선결: 프론트 전용 공유는 링크를 열 공개 웹페이지 배포가 전제 — 현재 SPA 미배포)

### 기능 상세
- **사용자**: 로그인 사용자(공유자), 비로그인(수신자)
- **권한**: 발급/폐기는 소유자, 조회는 인증 불필요
- **시나리오**: 소유자가 공유 → 짧은 링크 발급 → 수신자가 비로그인으로 열람 → (악보) 내 것으로 복제
- **동작 조건**: `제안`
  ```
  POST   /v1/chord-projects/{publicId}/share   → { shareToken, shareUrl }   // 멱등: 있으면 재사용
  GET    /v1/share/{token}                     → 차트 페이로드 (인증 불필요)
  DELETE /v1/chord-projects/{publicId}/share   → 폐기
  ```
  악보 프로젝트도 동일 패턴 + **악보 import(복제) 경로** 추가.
- **검증 조건**: 폐기하면 링크가 404.
- **기대 결과 및 완료 기준**
  - [ ] 짧은 링크 발급 + 비로그인 브라우저에서 열림 + 폐기 시 404

## 2. 코드차트 폴더 서버 영속  ⬜ 미시작  (← BR-9)

### 기능 요약
"내 코드차트" 폴더를 서버에 저장해 기기 간 동기화한다.

### 상황 설명
폴더 기능이 브라우저 localStorage 목업(`jazzify.myCharts.mock-v4`)이라, 다른 기기에서 안 보이고 로그아웃 정리 시 폴더 구조가 통째로 사라진다.

### 기능 상세
- **사용자**: 로그인 사용자
- **권한**: 본인 폴더
- **시나리오**: A기기에서 폴더 생성/이동 → B기기 로그인 → 동일하게 보임
- **동작 조건**: `제안` — 폴더 CRUD + 프로젝트 이동
  ```
  GET/POST/PATCH/DELETE /v1/folders (+ 하위 처리 정책 명시)
  PATCH /v1/chord-projects/{publicId} { folderId }   // 폴더로 이동
  ```
- **검증 조건**: A기기 폴더가 B기기 로그인 후 그대로.
- **기대 결과 및 완료 기준**
  - [ ] 폴더 기기 간 동기화 (트리 UI는 완성, 스토어만 교체)

## 3. "내 릭" 소유자 필터  ⬜ 미시작  (← BR-10)

### 기능 요약
"내 릭" 화면이 본인 릭만 반환하게 소유자 필터를 추가한다.

### 상황 설명
"내 릭"이 `GET /v1/licks`를 그대로 불러 소유자 필터가 없어 **남의 릭이 "내 릭"에 보인다.**

### 기능 상세
- **사용자**: 로그인 사용자
- **권한**: 본인 콘텐츠
- **시나리오**: 내 릭 화면 → 본인 릭만 표시
- **동작 조건**: `GET /v1/licks?owner=me` 또는 `GET /v1/users/me/licks`. 솔로(`/v1/solos`)도 같은 패턴 필요 여부 검토.
- **검증 조건**: 다른 사용자 릭이 "내 릭"에 나타나지 않음.
- **기대 결과 및 완료 기준**
  - [ ] 내 릭 = 본인 릭만

## 4. 솔로 목록 서버측 필터·검색  ⬜ 미시작  (← BR-11)

### 기능 요약
솔로 목록에 연주자·조성·박자·텍스트 검색 파라미터 + 페이지네이션 연동.

### 상황 설명
`GET /v1/solos`에 검색 파라미터가 없어 **프론트가 받아온 페이지 안에서만** 걸러, 페이지네이션과 어긋나 결과 수가 불완전하다.

### 기능 상세
- **사용자**: 로그인 사용자
- **권한**: 로그인
- **시나리오**: 연주자/조성/검색어로 필터 → 전체 결과에서 정확히 페이지네이션
- **동작 조건**: `?performer=&key=&meter=&q=` + 페이지네이션 연동. (facet용 `/performers`·`/composers`는 이미 있음)
- **검증 조건**: 필터 적용 시 전체 결과 기준 정확한 개수/페이지.
- **기대 결과 및 완료 기준**
  - [ ] 서버측 필터·검색 + 페이지네이션 정합

### 기능 상세

- **권한**: —

- **동작 조건**: 택1 — ① 생성 전체를 트랜잭션으로 묶기 ② 미참조 파일 주기적 GC ③ 실패 시 보상 삭제(`DELETE /v1/storage-files/{id}`) 보장.
- **검증 조건**: 생성 실패 후 스토리지에 미참조 파일 없음.

## 7. 오류 응답 `detail` 제거  ⬜ 미시작  (← BR-22)  [보안]

### 기능 요약
운영 오류 응답에서 내부 예외 문자열(`detail`)을 빼고 `code`/`message`만 반환한다.

### 상황 설명
오류 응답에 `detail`(내부 예외 문자열)이 들어온다. 프론트는 화면에 안 띄우고 콘솔에만 찍지만, **API를 직접 호출하면 스택·SQL·내부 경로가 그대로 노출**된다(공격자에게 지도 제공).

### 기능 상세
- **사용자**: 외부 API 소비자, 공격자(위협)
- **권한**: —
- **시나리오**: 오류 발생 → 응답에 내부 정보 없음
- **동작 조건**: 운영 환경 응답에서 `detail` 제거, `code`/`message`만. 디버깅은 서버 로그 + 상관관계 ID(`traceId`)로 대체.
- **검증 조건**: 오류 응답에 스택/SQL/경로 문자열 미포함.
- **기대 결과 및 완료 기준**
  - [ ] 운영 오류 응답에서 `detail` 제거
