### 상황 설명
현재 공유는 차트 전체를 URL 해시에 통째 인코딩하는 프론트 전용 v1(`/v?d=<base64url>`)이다. 문제: 차트가 크면 URL 폭증(메신저가 링크 자름), 원본 수정이 링크에 반영 안 됨(스냅샷), 조회수·만료·폐기 불가, 악보는 보기 전용이라 "내 것으로 복제"할 백엔드 경로가 없음. (🔴 선결: 프론트 전용 공유는 링크를 열 공개 웹페이지 배포가 전제 — 현재 SPA 미배포)

- **2026-07-29 재확인**: 백엔드에 share/shareToken 관련 코드·엔드포인트 0건 — 미착수.

### 기능 상세
- **사용자**: 로그인 사용자(공유자), 비로그인(수신자)
- **권한**: 발급/폐기는 소유자, 조회는 인증 불필요
- **시나리오**: 소유자가 공유 → 짧은 링크 발급 → 수신자가 비로그인으로 열람 → (악보) 내 것으로 복제
- **동작 조건**: `제안`
  ```
  POST   /v1/chord-projects/{publicId}/share   → { shareToken, shareUrl }   // 멱등: 있으면 재사용
  GET    /v1/share/{token}                     → 차트 페이로드 (인증 불필요)
  DELETE /v1/chord-projects/{publicId}/share   → 폐기
  ```
  악보 프로젝트도 동일 패턴 + **악보 import(복제) 경로** 추가.
- **검증 조건**: 폐기하면 링크가 404.
- **기대 결과 및 완료 기준**

## 5. 업로드 실패 시 고아 파일 정리  🟡 진행중 — 레거시 경로만 잔여  (← BR-12)

### 기능 요약
업로드 후 후속 생성이 실패해도 참조 없는 파일이 남지 않게 한다. (신규 preprocess/OMR 파이프라인은 완료)

### 상황 설명
**완료된 부분**: 신규 preprocess/OMR 파이프라인은 3중으로 완비됐다 — ① 트랜잭션(`ProjectPreprocessService.confirm()` 이 `@Transactional`) ② 실패 시 보상 삭제(`StorageFileEventListener.java:23-31`) ③ 주기 GC(`OmrWorkspaceCleanupScheduler` 30분, `ProjectPreprocessCleanupScheduler` 10분).

**남은 부분**: 레거시 storage-file 경로. `domain/storagefile/` 에는 `@Scheduled` 가 0건이고, 백엔드 `SheetProjectCreateRequest` 에서 `storageFileIds` 필드가 이미 사라졌는데도 프론트 `MySheetProjectsPage.tsx:239-247` 은 여전히 `uploadStorageFile()` → `createSheetProject({ storageFileIds })` 를 호출한다. 즉 **업로드가 성공해도 그 파일은 무조건 미참조 고아가 된다.** 실질 잔여 과제는 이 프론트 경로 수정이다.

### 기능 상세
- **사용자**: 로그인 사용자(간접)
- **권한**: —
- **시나리오**: 악보 프로젝트 생성 → 업로드한 파일이 실제로 프로젝트에 참조됨(또는 애초에 별도 업로드를 하지 않음)
- **동작 조건**
  - 프론트(잔여 과제): `MySheetProjectsPage` 업로드 경로를 현행 계약(project-preprocess → confirm)으로 교체해 `storageFileIds` 사용을 중단한다.
  - 백엔드: 레거시로 이미 쌓인 미참조 `storage_file` 1회성 정리 + `domain/storagefile` 미참조 GC 필요 여부 판단.
- **검증 조건**: 악보 프로젝트 생성 후 새로 생기는 미참조 `storage_file` 이 0건.
- **기대 결과 및 완료 기준**
  - [x] 신규 preprocess/OMR 경로 고아 미발생(트랜잭션 + 보상 삭제 + 주기 GC) — **완료(2026-07-29 소스 확인)**

- **2026-07-29 재확인**: 여전히 노출됨. 실측 예 — 로그인 실패 시 `{"code":"GLOBAL_006","detail":"Bad credentials"}`. `shared/web/ErrorResponse.java:21,42` 가 `e.getDetail()` 을 그대로 실어 보낸다. (500 응답에는 `detail` 이 없어, 나머지 예외 경로만 정리하면 된다.)

- **시나리오**: 오류 발생 → 응답에 내부 정보 없음

- **검증 조건**: 오류 응답에 스택/SQL/경로 문자열 미포함.
