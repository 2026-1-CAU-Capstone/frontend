# 2026-07-23 · RAG 코퍼스 백엔드 이관(migrate) 요구사항 3건

🏷 **범주(태그):** RAG·화성 검색(HarmoRAG)
RAG 코퍼스 원본이 **프론트 레포**(루트 `data/explanation/`, `frontend/data` 심링크)에 394개 있는데, 백엔드는
그중 **22개만** 색인 중이다(5.6%). 프론트에서 코퍼스를 없애고 **백엔드를 단일 소스**로 만들려면, 먼저 나머지
**372개를 백엔드로 이관·색인**해야 한다. 단 상당수가 백엔드 파서가 요구하는 섹션 포맷이 아니라 그대로는 색인되지 않는다.

## 현황 (2026-07-23 실측)
| 분류 | 프론트 원본(루트 data/explanation) | 백엔드 색인 | 미이관 | 포맷 |
|---|---|---|---|---|
| standards | 39 | 20 | **19** | 구조화(`### N-N.` 섹션) — 즉시 색인 가능 |
| lessons | 10 | 2 | **8** | 비구조화(이론 강의체, 섹션 없음) |
| 이지원재즈 | 345 | 0 | **345** | 전사형(유튜브 자막 + `channel/url/duration` 헤더) |
| **합계** | **394** | **22** | **372** | |

- 백엔드 색인분(22)은 프론트 원본의 **완전한 부분집합**(standards 20 전부 루트에 존재).
- 백엔드 DB: 현재 `rag_document 22 / rag_vector 285`.

## 진행 현황
범례: ✅ 완료 · 🟡 진행중 · ⬜ 미시작
- ⬜ 1. 구조화 코퍼스(standards 19) 이관 + 재색인 — 동일 포맷, 파일 복사만
- ⬜ 2. 비구조화 코퍼스(lessons 8 + 이지원재즈 345 = 353) 청킹 전략 추가 + 이관
- ⬜ 3. 코퍼스 단일 소스화 — 전량(394) 이관 검증 후 프론트 레포에서 제거

## 참고 경로 (구현 시 대조)

- **프론트 원본 코퍼스(이관 대상)**: 레포 루트 `data/explanation/{standards,lessons,이지원재즈}/` (프론트는 `frontend/data` 심링크로 참조만 하고 코드에서 직접 쓰지는 않음 — 순수 저장소).
- **백엔드 색인 소스**: `backend/data/explanation/{standards,lessons}/` (실제 폴더, 22개). 여기에 파일을 추가하면 `RagBootstrapRunner` 가 기동 시 색인.
- **백엔드 청커**: `backend/.../rag/service/implementation/RagFileChunker.java` — `SECTION_PATTERN`(`(\d+-\d+)\. 제목`) + `INSTRUCTION_PATTERN`/`RESPONSE_PATTERN`(`**instruction:** / **response:**`) 으로 청크를 뽑는다. **이 패턴이 없으면 청크 0개 → `RAG_014`(섹션 추출 실패)로 색인 거부.**
- **메타 패턴**: 같은 파일 `META_PATTERNS` 가 `곡명/작곡/센터 키/형식/강의 출처/분석 대상 곡/url` 을 인식. 이지원재즈의 `channel/duration/language` 는 미인식.

## 1. 구조화 코퍼스(standards 19) 이관 + 재색인  ⬜ 미시작

### 기능 요약
루트 `data/explanation/standards/` 에만 있고 백엔드에 없는 standards 19개를 백엔드 색인 대상에 추가한다.

### 상황 설명
이 19개는 백엔드에 이미 색인된 standards 20개와 **동일한 구조**(`### N-N.` 섹션 + instruction/response)임을 확인했다(19/19 섹션 포맷 보유). 즉 **파일만 백엔드 색인 소스에 넣으면** 기존 파서가 그대로 청킹·색인한다. 추가 개발 없음.

### 기능 상세
- **동작 조건**: 루트 `data/explanation/standards/` 의 미이관 19개 파일을 백엔드 색인 소스(`backend/data/explanation/standards/`)에 반영 → 재기동 시 `RagBootstrapRunner` 가 색인(내용 비교로 중복 방지).
- **검증 조건**: 재색인 후 standards 문서 수 = 39. `GET /v1/rag/documents?sourceType=standard` 로 확인.
- **기대 결과 및 완료 기준**
  - [ ] standards 39개 전부 색인
  - [ ] 각 문서 `chunkCount > 0`

## 2. 비구조화 코퍼스(lessons 8 + 이지원재즈 345) 청킹 전략 추가 + 이관  ⬜ 미시작

### 기능 요약
섹션 포맷이 없는 전사형/강의체 코퍼스 353개를 색인할 수 있도록 **청킹 전략을 추가**하고 이관한다.

### 상황 설명
- **이지원재즈 345개**: 유튜브 강의 전사(자막). 상단에 `channel: / url: / duration: / language:` 헤더 + 이후 **통짜 자연어 문단**. `### N-N.` 섹션·instruction/response가 **전혀 없다**(345개 중 구조화 0개).
- **lessons 8개**(Advanced Piano Voicings 등 이론 강의): `url :` 헤더는 있으나 역시 섹션/instruction 포맷 아님(8개 중 구조화 0개).

현재 `RagFileChunker` 는 `SECTION_PATTERN` 으로만 청크를 뽑으므로, 이 353개는 넣어도 **청크 0개 → `RAG_014` 로 색인 거부**된다(실측: admin 문서 추가 시 동일 에러 확인). 그래서 단순 복사로는 안 되고 **비구조화 텍스트용 청킹 경로**가 필요하다.

### 기능 상세
- **동작 조건** (택1 또는 조합, 백엔드 설계에 맡김 — `제안`)
  1. **길이/문단 기반 청킹 폴백**: 섹션 패턴이 안 잡히는 문서는 일정 토큰/문자 길이(예: 500~800자, 오버랩 포함) 또는 문단 단위로 청킹한다.
  2. **전사형 sourceType 신설**: 이지원재즈처럼 유튜브 전사는 `sourceType` 을 `standard`/`lesson` 과 구분(예: `transcript`)하고, `channel/url/duration/language` 를 메타로 인식(현재 `META_PATTERNS` 확장). `url` 은 문서 #24/#25 의 원본 링크 노출과 연결된다.
  3. 청킹 실패 시 문서 단위 1청크라도 색인(전량 검색 대상에 포함)할지 여부 결정.
- **검증 조건**
  - lessons 10개 전부 + 이지원재즈 345개 색인, 각 `chunkCount ≥ 1`.
  - 이지원재즈 문서 검색 시 결과에 등장(`GET /v1/rag/search?q=...`), 원본 URL 노출.
- **기대 결과 및 완료 기준**
  - [ ] 비구조화 353개 색인(청크 0으로 거부되지 않음)
  - [ ] 이지원재즈 전사형 메타(channel/url/duration) 보존 + 원본 URL 노출
  - [ ] 검색에서 전사형 코퍼스가 회수됨

## 3. 코퍼스 단일 소스화 — 전량 이관 검증 후 프론트 레포에서 제거  ⬜ 미시작

### 기능 요약
394개 전량이 백엔드에 색인된 것을 검증한 뒤, 프론트 레포(루트 `data/explanation/`)의 코퍼스를 제거해 **백엔드를 유일 소스**로 만든다.

### 상황 설명
지금은 코퍼스 원본이 프론트 레포에 있고 백엔드가 일부만 복사해 쓰는 이중 상태다. 프론트는 이 폴더를 코드에서 직접 쓰지 않으므로(순수 저장소), 전량 이관만 끝나면 프론트 레포에서 안전하게 뺄 수 있다. **단 1·2가 끝나 백엔드 색인이 394로 확인되기 전에는 절대 제거하지 않는다**(현재 지우면 372개 영구 손실).

### 기능 상세
- **동작 조건**: 1·2 완료 → 백엔드 `rag_document` 수가 원본과 일치(≈394) → 그 뒤 프론트 레포에서 루트 `data/explanation/` 코퍼스 제거(프론트 작업).
- **검증 조건**: `GET /v1/rag/health` 의 `documentCount` ≈ 394. 대표 문서(이지원재즈 포함) 검색·상세·청크 조회 정상.
- **기대 결과 및 완료 기준**
  - [ ] 백엔드 색인 문서 수 = 원본 총량(≈394)
  - [ ] 이관 검증 후 프론트 레포 코퍼스 제거(백엔드 단일 소스)
  - [ ] 제거 후에도 채팅 RAG·admin 관리 화면 정상

> 순서 주의: **1 → 2 → (검증) → 3**. 3(프론트 제거)은 반드시 백엔드 색인 검증 후. 프론트 RAG "코드"(harmorag/RagDebugPanel/채팅 인용)는 이관 대상이 아니라 백엔드를 쓰는 클라이언트이므로 그대로 둔다.
