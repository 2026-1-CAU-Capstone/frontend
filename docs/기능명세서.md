## 1. 제품 개요

Jazzify는 재즈 연주자·학습자를 위한 **코드차트/리드시트 분석 + AI 화성학 튜터 + 백킹트랙 연습** 통합 플랫폼이다.

| 핵심 가치 | 내용 |
| --- | --- |
| **분석** | 1,460곡 표준 + 사용자 차트를 ii-V-I·세컨더리 도미넌트·모달 인터체인지로 자동 분석·시각화 |
| **AI 튜터** | RAG 채팅으로 출처(유튜브 딥링크) 달린 답변 + DB 릭 추천 |
| **연습** | 풀밴드 자동 반주(콤핑+워킹베이스+드럼, 13장르), 12키 릭 연습, 구간 루프 |
| **자료화** | OMR로 이미지 악보 디지털화, 릭/솔로 DB(WJazzD 8,000+) 검색 |

**플랫폼**: 웹(데스크톱/태블릿) + iOS 네이티브(Capacitor) · HashRouter SPA

| F1.13 | **내부 스튜디오 분리 — 별도 진입점·별도 배포** (2026-08-08) | 어드민 도구를 실서비스에서 떼어내 **독립 앱**으로 만들었다. `index.html → src/main.tsx → App`(실서비스) / `studio.html → src/studio/main.tsx → StudioApp`(스튜디오) 두 진입점이고, 껍데기(라우터·프로바이더 스택·오디오 수명주기·업로드 큐·설정 모달)는 `AppShell` 하나로 공유한다 — 각자 적어두면 한쪽에 프로바이더를 추가할 때 다른 쪽을 빼먹어 갈라진다.<br>**분리 방식은 실측으로 정했다**: 페이지에서 import 를 따라간 결과 스튜디오 전용은 12개 파일(전체 288개 중 4%)이고 공유가 59% 였다. repo 를 쪼개면 그 60% 가 첫날부터 갈라지므로 한 트리 안에서 경계만 만들었다(`packages/core` 방식은 198개 파일 이동 대비 얻는 게 `package.json` 분리뿐).<br>경계는 eslint `no-restricted-imports` 로 **빌드가 막는다**(공유·실서비스 → `src/studio/**` 금지, 역방향 허용). 사이드바는 각 페이지가 직접 렌더하던 것을 `sidebarSlot` 주입으로 바꿨다 — 그러지 않으면 스튜디오의 Solo Database 에 앱 채팅 사이드바가 그대로 뜬다(실제로 그랬다).<br>**같은 페이지, 다른 권한** — `/editor`·`/input` 은 실서비스에서 ProtectedRoute(로그인만)인데 스튜디오에서는 AdminRoute 다. 파일은 한 벌이고 권한만 다르게 태운다. `/licks`·`/solos`(관리 화면)는 실서비스에서 아예 제거했다. 제작·디버그 도구(🗂 큐 기록·응답값 원문)는 `lib/surface` 의 `useIsStudio()` 로 가른다 — 예전엔 `isAdminUser()` 로 갈라서 **실서비스에서 admin 으로 로그인하면 그대로 보였다**.<br>스튜디오 사이드바는 앱과 치수·모양을 맞추고(244/52px·38px 항목) 내용만 예전 우측 하단 Admin 드롭업의 도구 11종을 분석/데이터/파이프라인 3묶음으로 옮겼다(그 독은 삭제). 홈은 앱과 레이아웃이 같고 **채팅 히어로만 없다**. 로그인 화면은 소셜 로그인·회원가입을 렌더하지 않고 전용 워드마크(`jazzify-studio.png`)를 쓴다.<br>빌드는 한 번에 하나만 한다(`npm run build:studio` → `dist-studio`, studio.html → index.html). 둘을 같은 dist 에 넣으면 공개 배포에 studio.html 이 따라가 URL 만 알면 열린다. dev 는 실서비스 5173 · 스튜디오 5174(`strictPort` — 조용히 밀리면 백엔드 CORS 목록에 없어 로그인이 403 난다).<br>**검증**: dist(실서비스)에 `RagAdminPage`·`STUDIO_NAV`·`Jazzify Studio`·`큐 기록`·`응답값 받기`·`백엔드:` **전부 0건**, dist-studio 에는 존재<br>**에디터 범위도 화면마다 다르다 (2026-08-10)** — 에디터의 타입 넷(Solo·Lick·Comping·Lead Sheet)은 전부 **사내 수집 DB** 로 저장하는 어드민 분류축이다. 실서비스에 남는 건 릭 하나뿐이라(사용자 릭 = `/v1/licks`) 타입 칩을 스튜디오 전용으로 두고, 실서비스 에디터는 `내 릭`의 **만들기·수정으로만 열리는** 릭 편집기로 좁혔다. 사이드바의 직접 진입(`악보 만들기`)은 제거했다 — 빈 에디터로 바로 들어가면 저장할 대상이 없다. URL(`?mode=solo`)·localStorage 에 남은 값으로 어드민 모드로 들어오는 경로도 막았다(들어오면 사용자가 자기 악보를 사내 DB 에 쓴다).<br>어드민 저장소를 번들에서 빼는 데 **런타임 `useIsStudio()` 만으로는 부족했다** — 분기가 살아 있어 청크 파일이 그대로 배포된다. `vite.config` define 으로 `import.meta.env.VITE_STUDIO` 를 리터럴로 박고 저장 분기를 그 플래그로 감싸 죽은 코드로 제거했다: dist(실서비스)에 `jazzify_lead_sheet_entries`·`jazzify_comping_entries`·`LEAD_SHEET_STYLES` **0건**, dist-studio 에는 존재 | 👨‍💻 | FE | ✅ |

### ⬜ 미해결 — 보표 종류 변경(⇆) 시 음표 도메인이 변환되지 않는다

드럼 보표의 `keys`는 **GM 퍼커션 절대값**(킥=`c/2`)이고 일반 보표의 `keys`는 **음높이**다. ⇆로 종류를 드럼↔일반으로 바꾸면 `changePartKind`가 확인 대화상자로 경고만 하고 **데이터는 그대로 둔다**. 그 결과 ① 드럼→일반: GM 키가 음높이로 해석돼 오선 아래 80px·**덧줄 4개**의 뭉치가 되고 ② 일반→드럼: 음높이가 `drumDisplayForGm` 폴백으로 죄다 스네어 자리(c/5)에 몰린다. 2026-08-01 행 간격을 136px로 넓혀 **아래 보표를 침범하는 문제는 막았지만**, 음표 자체가 무의미한 것은 그대로다. 조치 후보: (a) 종류 변경 시 변환(드럼→일반은 손실이 커 사실상 불가) (b) 음표가 있는 보표는 도메인을 넘는 종류 변경을 막고 "새 보표 추가"로 유도. **(b) 권장 — 제품 결정 필요.**

## 7. 비기능 요구사항 (NFR)

### 7.1 보안

- **시크릿**: `VITE_`는 공개 가능 값 전용. API 키·토큰은 백엔드 보관 필수 (현 위반: C1).
- **인증**: JWT(단기 access, localStorage) + HTTP-only refresh 쿠키 + RTR(재사용 감지 무효화) + 멀티탭 Web Locks.
- **계정 격리**: 로그인/로그아웃 시 사용자범위 캐시 8종·chartEdit prefix·IndexedDB OMR 이미지 정리.
- **CSP**: 외부 스크립트 차단(youtube만)·frame/object 제한 메타. SRI·폰트 셀프호스팅 잔존.
- **에러 노출**: 사용자에겐 `message`만, `detail`은 dev 콘솔만.
- **개선 권고**: access token 메모리/httpOnly화, Anthropic 호출 백엔드 일원화, npm audit 주기 점검.

### 7.2 성능

- **코드 스플리팅**: VexFlow/OSMD(~1.1MB)를 차트/악보 페이지에만 lazy 로드.
- **사운드폰트 캐시**: smplr 샘플 IndexedDB 캐시.
- **재생 정확도**: 백킹은 Web Audio lookahead(200ms). 에디터/12키는 setTimeout 기반(§8 R8 공유훅 단일화).
- **OMR 비동기**: 폴링 + in-flight dedup으로 중복 POST 방지.

### BR-18. `chord_context` 구조화 객체가 RAG agent로 전달되지 않음 — 모호성 게이팅 쿼리 분해 미작동 미해결 HIGH BE RAG

### BR-45. Solo `sheetData` null 직렬화로 응답이 4.9배 팽창 구현완료 HIGH BE
