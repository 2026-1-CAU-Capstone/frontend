# 로컬 백엔드 전환 (프론트 설정)

프론트는 **항상 `localhost:5173`** 이고, **백엔드만** 운영 ↔ 로컬(IntelliJ)로 바뀐다.

---

## 1. 전환 방법 — 명령 두 개가 전부

```bash
npm run dev          # → 백엔드: https://jazzify.p-e.kr   (운영, 기본)
npm run dev:local    # → 백엔드: http://localhost:8080    (내 로컬)
```

켤 때 찍히는 이 한 줄로 **지금 어디에 붙어 있는지** 항상 확인된다.

```
➜  API 프록시:  /api → http://localhost:8080  (로컬 백엔드)
➜  API 프록시:  /api → https://jazzify.p-e.kr  (운영 서버)
```

### 그 외 주소를 쓸 때만 (8080이 아닌 경우)

```bash
JAZZIFY_API_TARGET=http://localhost:9090 npm run dev      # 그때그때
echo 'JAZZIFY_API_TARGET=http://localhost:9090' >> .env.local   # 고정
```

> `.env.local`은 repo 루트(`../.env.local`)와 `frontend/.env.local` 둘 다 읽는다(frontend 우선).
> 여기에 `JAZZIFY_API_TARGET`을 넣어두면 `npm run dev`도 그쪽을 본다 — 운영으로 되돌리려면 그 줄을 지운다.

---

## 2. 주의사항 (중요한 순서대로)

### ① dev 서버 재시작 필수
`vite.config.ts`는 **부팅 시 1회만** 읽힌다. env를 바꿨으면 HMR로는 안 되고 서버를 껐다 켜야 한다.

### ② 값은 호스트까지만 — `/api`를 붙이지 말 것
```bash
JAZZIFY_API_TARGET=http://localhost:8080        # ✅
JAZZIFY_API_TARGET=http://localhost:8080/api    # ❌ → /api/api/v1/... 로 404
```
경로(`/api/v1/...`)는 프록시가 **그대로** 넘긴다.

### ③ `rewrite`를 절대 넣지 말 것 (vite.config.ts)
백엔드 context-path가 `/api`라서(`application-dev.yml`) `/api`를 떼면 **전부 404**다.
```js
// ❌ 넣으면 안 됨
rewrite: (p) => p.replace(/^\/api/, '')
```

### ④ 로컬 백엔드를 먼저 띄울 것
백엔드가 안 떠 있으면 프론트 요청이 `ECONNREFUSED`로 실패한다. IntelliJ에서 `dev` 프로파일로 실행 후 확인:
```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/v1/rag/health   # 200 이어야 함
```

### ⑤ 로그인 상태는 백엔드마다 별개
운영↔로컬을 오가면 **토큰·계정이 서로 다르다.** 전환 후 401이 나면 정상이니 다시 로그인하면 된다.
(로컬 DB에 계정이 없으면 회원가입부터 필요)

---

## 3. 프론트 코드는 건드릴 게 없다

- API 호출부(`src/api/*.ts`) 4곳은 dev에서 이미 `/api` 상대경로를 쓴다 → **수정 불필요**.
- CORS 설정도 불필요. 프록시가 same-origin으로 중계하므로 브라우저가 CORS로 막지 않는다.
  (프록시를 쓰는 진짜 이유: RefreshToken **HTTP-only 쿠키**를 first-party로 받기 위함)

## 4. 참고 — 백엔드 URL 구조

```
호스트         : http://localhost:8080   (운영: https://jazzify.p-e.kr)
context-path  : /api                     ← 전역 접두사
컨트롤러       : /v1/{도메인}
─────────────────────────────────────
최종 URL      : http://localhost:8080/api/v1/...
```

- 응답은 전부 `{ "data": ... }` 봉투로 감싸진다.
- 공개(토큰 불필요): `/v1/auth/**`, `/v1/rag/health`, `/v1/embedding/health`, swagger.
  그 외는 `Authorization: Bearer` 필요.
- 로컬 Swagger: http://localhost:8080/api/swagger-ui.html
