# Jazzify 프론트엔드 — 구조 지도 (두 앱 · 폴더 · 페이지 · 죽은 코드)

> 이 문서 하나만 읽으면 "이 앱이 뭐로 굴러가는지"를 그림처럼 파악할 수 있게 쓴 지도다.
> 처음 보는 사람 기준, 예시 위주. **모든 수치는 작성 시점 자동 스캔 실측값**이다(추정 없음).
>
> 2026-07-29 판(문서 #34 v2)을 전면 갱신했다. **가장 큰 변화는 앱이 하나가 아니라 둘이 된 것**이다.

---

## 0. 한 줄로

**Jazzify = 재즈 악보(코드/멜로디)를 화면에 그려주고, 브라우저에서 실제로 반주·연주해 들려주고, AI로 화성 분석·질문답변까지 해주는 웹앱.**

React 19 + TypeScript 5.9 + Vite 8로 만들고, 악보는 VexFlow 5로 그리고, 소리는 Web Audio로 낸다. 스타일은 styled-components 6, 라우팅은 react-router 7(HashRouter). 데이터는 Spring 백엔드(`jazzify.p-e.kr`)에서 가져온다. Capacitor 8로 iOS 앱으로도 감싼다.

**규모**: `src/` 아래 TS/TSX **309개 파일 · 108,119줄**.

## 1. 큰 그림 ① — 앱이 **둘**이다 (2026-08 신설)

예전엔 앱이 하나였고 관리자 도구가 그 안에 섞여 있었다. 지금은 **진입점이 둘로 갈렸다.**

| | 실서비스 | 내부 스튜디오 |
|---|---|---|
| HTML | `index.html` | `studio.html` |
| 진입 | `src/main.tsx` → `Root.tsx` → `App.tsx` | `src/studio/main.tsx` → `StudioRoot.tsx` → `StudioApp.tsx` |
| 누가 쓰나 | 일반 사용자 | 우리(사내 큐레이션) |
| 가드 | `ProtectedRoute`(로그인) | `AdminRoute`(ADMIN/MANAGE) |
| 배포 | `jazzifydevelop.netlify.app` | `jazzifystudio.netlify.app` |
| dev 포트 | 5173 (`npm run dev`) | 5174 (`npm run dev:studio`) |
| 빌드 | `npm run build` → `dist` | `npm run build:studio` → `dist-studio` |

**한 트리 안에서 경계만 만들었다** — repo 를 쪼개지 않았다. 실측으로 정한 결정이다:

| 구분 | 파일 | 비중 | 줄 |
|---|---:|---:|---:|
| **공유(둘 다 씀)** | 226 | **78.5%** | 68,258 |
| 실서비스 전용 | 29 | 10.1% | 15,706 |
| 스튜디오 전용 | 32 | 11.1% | 12,024 |

공유가 78%다. repo 를 쪼개면 그 78%가 첫날부터 갈라진다. 그래서 **경계는 eslint 가 막는다** — `no-restricted-imports` 로 실서비스·공유 코드가 `src/studio/**` 를 import 하면 **빌드가 실패**한다(역방향은 허용).

껍데기(라우터·프로바이더 스택·오디오 수명주기·업로드 큐·설정 모달)는 **`AppShell.tsx` 하나로 공유**한다. 각자 적어두면 한쪽에 프로바이더를 추가할 때 다른 쪽을 빼먹어 갈라진다.

### 같은 파일, 다른 행동 — `lib/surface.ts`

같은 페이지가 두 앱에서 다르게 굴어야 할 때 쓴다. `SurfaceContext`(`'app' | 'studio'`)를 각 루트가 심고, `useIsStudio()` 로 읽는다.

- 에디터는 실서비스에서 **릭 편집 전용**(타입 칩 없음), 스튜디오에서 **네 타입**(Solo·Lick·Comping·Lead Sheet)
- 제작·디버그 도구(큐 기록·응답값 원문·백엔드 배지)는 스튜디오에서만 보인다

> ⚠️ 예전엔 이걸 `isAdminUser()` 로 갈랐다 — 그래서 **실서비스에서 admin 으로 로그인하면 어드민 UI가 그대로 보였다.** 로그인한 사람이 누구인지가 아니라 **어느 앱인지**로 갈라야 한다.

### 번들에서 빼야 할 땐 런타임 플래그로 부족하다

`useIsStudio()` 는 런타임 값이라 분기가 코드에 남고, 청크 파일이 그대로 배포된다. 어드민 저장소처럼 **번들에서 아예 빼야 하는 것**은 `vite.config` 의 define 이 박아 주는 빌드 타임 리터럴로 감싼다:

```ts
if (import.meta.env.VITE_STUDIO) { /* 실서비스 빌드에서 죽은 코드로 제거됨 */ }
```

## 2. 큰 그림 ② — 화면에서 4갈래로 갈린다

사용자가 보는 것은 **페이지(React 화면)** 다. 각 페이지는 아래 **4가지 일**로 갈라져 나머지를 부른다.

1. **① 악보 그리기** — 코드진행은 `LeadSheet`, 음표 악보는 `NoteSheet`. 둘 다 내부에서 **VexFlow**를 쓴다.
2. **② 소리 내기** — `GlobalPlayer`(앱 전체에 하나뿐인 재생기)가 지휘. 코드진행이면 **backing 엔진**이 베이스·드럼·피아노를 즉석 합성하고, 음표 악보면 멜로디를 재생. 재생 중 "지금 몇 번째 마디/음표" 이벤트를 쏴서 화면 하이라이트를 맞춘다.
3. **③ 데이터 주고받기** — `src/api/*` 가 백엔드를 호출. 모든 응답은 `{ data: … }` 봉투. 로그인 토큰(Bearer)을 붙여 보낸다.
4. **④ AI** — `api/chat` 이 `/v1/chat/*/stream` 으로 답을 스트리밍. 코드 문맥(`chordContext`)을 실어 보내면 **HarmoRAG**(화성 특화 검색)가 근거를 붙여 답한다.

| 기둥 | 담당 | 핵심 파일/폴더 |
|---|---|---|
| ① 악보 그리기 | VexFlow 렌더 | `components/leadsheet/LeadSheet`, `components/notesheet/NoteSheet` |
| ② 소리 내기 | 재생 지휘 + 반주 합성 | `lib/player`, `lib/backing` |
| ③ 데이터 | 백엔드 호출 | `src/api/*` |
| ④ AI | 스트리밍 + RAG | `api/chat`, `components/chat` |

## 4. "이렇게 가면 이렇게 된다" — 예시 여정 5개

### 여정 A · 코드차트를 열고 ▶ 재생을 누른다
1. `/mychord` (**ChordPage**) → `api/chordProjects` 로 프로젝트 + 분석 로드
2. `chordProjectToLeadSheet` 로 화면용 데이터(`LeadSheetData`)로 변환
3. `<LeadSheet>` 가 VexFlow 로 코드칸 · 마디를 그림
4. ▶ 누르면 → `useGlobalPlayer().play({ kind: 'chart', … })`
5. `lib/backing/adapters/leadSheetToChart` 가 진행을 차트로 → backing 엔진이 베이스(`bass.ts`) · 드럼(`drums.ts`) · 피아노를 합성해 Web Audio 로 출력
6. 매 마디 `'bar'` 이벤트 → `LeadSheet` 의 현재 마디에 하이라이트

### 여정 B · AI에게 "이 F-7 왜 나온 거야?" 물어본다
1. 채팅 입력 → `api/chat` 이 `/v1/chat/chord-project/stream` 호출(본문에 `message` + `chordContext` + `useRag=true`)
2. 백엔드 **HarmoRAG** 가 화성 태깅 → 모호하면 서브쿼리 분해 → 벡터검색 → Claude
3. 답이 토큰 단위로 스트리밍되어 `components/chat` 이 실시간 렌더
4. 답 안에 인라인 릭/악보가 있으면 그 자리에서 VexFlow 로 그려줌(`chatChartParser`)

### 여정 C · 내 릭에서 릭을 만들거나 고친다
1. `/my-licks` (**MyLicksPage**) → `추가하기 → 에디터로 추가하기` 또는 항목 `수정`
2. `/editor?mode=lick` (**EditorPage**, 8,984줄 — 가장 큰 파일) → 자체 `renderSheet`(VexFlow)로 음표를 그림
3. 피아노 키보드 / MIDI / 단축키로 음표 입력, 마디가 다 차면 자동으로 다음 마디
4. 마디 위 `ChordCell` 에 코드 입력(**Tab** 으로 다음 칸 이동)
5. 저장 → `api/licks` 로 업로드 → `/my-licks` 로 복귀

> **실서비스 에디터는 릭 전용이다.** 타입 칩(Solo·Comping·Lead Sheet)은 스튜디오에만 있다 — 그 셋은 사내 수집 DB 로 저장하는 어드민 분류축이라, 실서비스에 두면 사용자가 자기 악보를 사내 DB 에 쓴다.
> 음표 편집기는 "재사용 컴포넌트"가 아니라 **EditorPage 페이지 안에** 들어 있다.

### 여정 D · 악보 사진을 올려 OMR로 악보를 만든다
1. 사진/PDF 업로드 → `api/storageFiles` 로 파일 저장 (PDF 는 `pdfToImage` 로 먼저 이미지화)
2. `api/sheetProjects` 의 생성 호출 → 서버가 OMR 큐에 넣는다
3. 폴러가 `omrStatus`(PENDING → PROCESSING → COMPLETED)를 감시
4. COMPLETED 되면 `omrResult`(원문 MusicXML)를 `omrResultToSheet` 로 `NoteSheetData` 로 변환
5. `<NoteSheet>` 읽기 전용 뷰어로 렌더

### 여정 E · 스튜디오에서 솔로를 큐레이션한다 (어드민)
1. `jazzifystudio` 로그인(`AdminRoute` — ADMIN/MANAGE 만)
2. `/solos` (**SolosPage**) → `api/solos` 로 사내 전역 Solo DB 목록
3. 항목 `수정하기` → `/editor?mode=solo` 로 `prefillSheet`(route state)를 넘겨 채워 열기
4. 고쳐서 저장 → `api/solos` 갱신 → `/solos?solo=…` 로 그 악보로 복귀

## 6. 안 쓰는 것 / 옛날 것 (죽은 코드 리포트)

자동 스캔 결과: **309개 소스 중 아무도 import 하지 않는 파일 = 21개.** 그중

- **테스트 16개**(`__tests__/*.test.ts`) — 정상(vitest 가 실행, import 대상 아님)
- **앰비언트 선언 4개**(`*.d.ts` — `styled.d.ts`·`soundtouchjs.d.ts`·`youtube-iframe.d.ts`·`url-import.d.ts`) — 정상(전역 타입 선언은 import 하지 않는다)

### 실제로 죽은 파일 — **1개**

| 파일 | 줄 | 정체 |
|---|---:|---|
| `hooks/useProjectPreprocess.ts` | 181 | 프로젝트 생성 전처리 훅(문서 #32 연동). `api/projectPreprocess` 는 살아 있는데 이 훅만 배선이 끊겼다 |

> 2026-07-29 판에서 지적한 **죽은 파일 10개(≈1,713줄)는 전부 정리됐다.** `data/irealMeta.ts`(1,461줄) · `LoginScreen`/`LoginModal` · `useNoteSheetPlayback` · `ProjectCreateModal` · `ChordOverlayLayer` · `Toggle` · `mergeOmrSheets` · `Logo` · `FuncBadge` — 모두 삭제됨.

### 참고 — 이 스캔의 한계
정적 import 그래프만 본다. **route state·문자열 키로만 연결되는 것은 잡지 못한다.** 예를 들어 `pages/ChordPage.tsx` 는 `App.tsx` 안의 인라인 `KeyedChordPage` 를 통해서만 쓰여서, 예전 감사에서 "스튜디오 전용"으로 오분류된 적이 있다. 지우기 전에 **문자열 검색으로 한 번 더 확인**할 것.

## 7. 한눈 요약 치트시트

- **화면 추가하려면** → `pages/`(또는 `studio/pages/`)에 파일 + 해당 라우팅 표(`App.tsx` / `StudioApp.tsx`)에 라우트. **두 표 중 어디에 넣을지가 곧 권한 결정이다.**
- **어드민 기능인가?** → `studio/` 에 두거나, 공유 파일이면 `useIsStudio()` 로 가른다. `isAdminUser()` 로 가르지 말 것(실서비스에서 새어 나온다).
- **번들에서까지 빼야 하면** → `import.meta.env.VITE_STUDIO` 로 감싼다(런타임 분기로는 청크가 배포된다).
- **코드차트 관련** → `LeadSheet` + `lib/backing` + `api/chordProjects`.
- **음표 악보 관련** → `NoteSheet`(보기) / `EditorPage`(편집) + `lib/note`.
- **악보 데이터 타입** → `data/sampleMelody.ts`(`NoteSheetData`·`MeasureInfo`·`NoteInfo`)가 원천.
- **소리 관련** → `lib/player`(지휘) + `lib/backing`(반주 합성).
- **코드 기호 해석·표기** → `lib/jazz-harmony`. **`splitChordParts` 를 반드시 거칠 것** — 따로 파싱하면 분수코드 베이스가 조용히 사라진다.
- **AI 관련** → `api/chat` + `components/chat` + (백엔드)HarmoRAG.
- **백엔드 타입** → `api/schema.d.ts`(스펙 자동생성) — 손으로 응답 타입 적지 말 것.
- **색** → `styles/theme.ts`(라이트) / `darkTheme.ts`(다크). 컴포넌트에 색을 하드코딩하지 말고 의미 토큰을 쓸 것. 라이트에만 있는 옅은 틴트는 `tint(light, dark)` 헬퍼로.
- **백엔드 없는 기능** → `data/*Data.ts` 에 localStorage 로 두고 **요구사항 문서를 올린다**. 임시라는 사실이 코드에 보여야 한다.
- **죽은 파일** → 지금 1개(`hooks/useProjectPreprocess.ts`).
