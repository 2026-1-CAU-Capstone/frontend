# 조성 추천 정확도 개선 — 77.7% → 84.5%

> 코드 차트에서 **코드 심볼만 보고** 곡의 조성을 맞히는 기능(`keySuggest`)의 정확도를
> 실측·개선한 기록. 채택 8건 / 기각 8건의 근거를 전부 남긴다.

## 0. 한눈에

| | 개선 전 | 개선 후 |
|---|---|---|
| **1순위 적중** | 1134 / 1460 (77.7%) | **1234 / 1460 (84.5%)** |
| 2순위 이내 | 89.9% | **92.3%** |
| 3순위 이내 | 92.1% | **94.1%** |
| 5순위 이내 | 94.9% | **96.0%** |
| 장조(1195곡) | — | 85.2% |
| 단조(265곡) | — | **81.5%** |

- **평가 코퍼스**: iReal Pro 1460곡(`public/jazz1460.json`). 곡마다 iReal Pro가 명시한
  조성이 정답 라벨로 들어 있어, 코드 진행만 주고 맞히는지 검정할 수 있다.
- **과적합 아님**: 곡을 홀·짝으로 갈라 따로 재도 **84.52% / 84.52%** 로 동일.
- 재현: `npx tsx scripts/keySuggestBenchmark.ts` (1460곡 약 10초)

## 1. 발단 — 사용자 제보

내 코드 차트의 **Tea For Two**(정답 Ab)에서 "조성이 다른 것 같아요 → **B♭ 장조**로 바꾸세요"라는
잘못된 추천이 떴다. 실제 데이터로 재현하니 정답 Ab는 2위였고, 파고들자 **독립적인 버그 두 개**가
겹쳐 있었다.

## 2. 채택한 개선 8건

| # | 내용 | 효과 |
|---|---|---|
| 1 | **코드 성질 정규화 버그 수정** | +2.6%p |
| 2 | 턴어라운드 종지 보정 | (1에 포함) |
| 3 | 피벗 코드 제외 | +1.3%p |
| 4 | 종지 인정 구간 제한 | +1.0%p |
| 5 | Krumhansl 음고류 프로파일 | +1.2%p |
| 6 | 세컨더리 도미넌트 엄격화 | +0.4%p |
| 7 | `minMaj7`(i△7) 단조 토닉 인정 | 단조 +0.7%p |
| 8 | **`firstTonic` 재평가** | +0.3%p (단조 +3.8%p) |

### 2-1. 코드 성질 정규화 버그 (가장 컸다)

`harmonyAnalyzer` 의 `QUALITY_MAP` 이 **대시(`-`) 표기만** 인식했다. `m7`·`maj7`·`m7b5`·`dim7`
같은 표기는 어떤 패턴에도 안 걸려 기본값 `'maj'` 로 떨어졌다.

```
"m7"    → maj   ← 마이너인데 메이저로 분석됨
"maj7"  → maj   (우연히 맞음)
"m7b5"  → maj
"dim7"  → maj
"-7"    → min7  (이것만 정상)
```

OMR·사용자 입력이 m 표기인 곡은 **코드가 통째로 메이저로 오분석**됐다. Tea For Two의 `Bbm7` 이
B♭**장조**의 으뜸화음으로 인정돼 조성 추천이 뒤집힌 것.

**수정**: 이미 `m7`/`maj7`/`mMaj7` 을 정확히 구분하는 표시용 정규화기(`normalizeQuality`)를
앞단에 태워 표기를 통일했다. 규칙을 두 벌 만들지 않았다.

> ⚠️ 이 버그는 조성 추천만이 아니라 **화성 분석 전반**(도수 배지·다이아토닉 판정·ii-V-I 탐지)에
> 영향을 준다. m 표기로 저장된 모든 차트가 영향권이었다.

### 2-2. 턴어라운드 종지 보정

재즈 리드시트는 종지(I) 뒤에 **처음으로 되돌아가는 턴어라운드**를 붙이는 게 보통이다.

```
Tea For Two 마지막:  … Ab6 | Cm7b5  F7b9
                        ↑진짜 종지    ↑턴어라운드
```

"맨 끝 코드"만 보면 정답 Ab가 종지 점수 24점을 통째로 잃고, 그 점수를 턴어라운드가 겨냥하는
ii(B♭m)가 가져간다. **되돌아가는 V7 + 그 ii를 건너뛴 자리**를 실질 마지막 코드로 본다.

### 2-3. 피벗 코드 제외

오답을 점수 항목별로 분해했더니 **`마지막 케이던스` 하나가 평균 +18.3점**으로, 나머지 항목을
전부 합친 것보다 컸다.

원인: 한 ii-V-I의 `I` 이면서 **곧바로 다음 ii-V의 `ii`** 가 되는 코드(피벗)를 종지로 인정하고
있었다. 그건 쉬어가는 종지가 아니라 통과점이다. 종지·체류 시간 계산에서 제외했다.

### 2-4. 종지 인정 구간 제한 (`FINAL_CADENCE_ZONE = 0.85`)

"마지막 완결 케이던스"는 30점 all-or-nothing 신호라 한 번 잘못 잡히면 곧바로 오답이 된다.
곡 중간의 부차 토닉화(브리지가 IV·vi로 닫히는 등)가 이걸 가로챘다.

→ **곡 뒤쪽 15% 안**에 있을 때만 인정. 32마디 곡이면 마지막 네 마디로, 재즈 스탠다드의 구조적
종지가 실제로 놓이는 자리다. 그 구간에 없으면 **아무도 가점받지 않는다**(엉뚱한 키에 주느니
신호 없음이 낫다).

스윕 결과 0.80~0.90이 고원, 0.95부터 급락(80.3%).

### 2-5. Krumhansl–Schmuckler 음고류 프로파일

1~4번이 "어디로 해결되는가"를 본다면, 이건 **"이 곡이 어느 음계에 사는가"** 를 직접 잰다.
직교 신호라 같은 다이아토닉 집합을 쓰는 나란한조·3음만 다른 동주조에서 힘을 쓴다.

코드 심볼밖에 없으므로 음표 대신 **코드 구성음**을 지속(박)으로 가중해 히스토그램을 만들고,
Krumhansl–Kessler(1982) 프로파일과 피어슨 상관을 낸다.

### 2-6. 세컨더리 도미넌트 엄격화

어떤 dom7이든 "무언가의 V7"로 해석될 여지가 있어(근음 4도 위가 다이아토닉이기만 하면 성립),
해결을 요구하지 않으면 **엉뚱한 조성도 거의 모든 도미넌트를 설명해 버린다.**
→ **실제로 해결될 때만** 설명으로 인정.

### 2-7. `minMaj7` 단조 토닉 인정

`i△7` 은 재즈 단조의 대표적 으뜸화음(라인 클리셰 i → i△7 → i7 → i6)인데 토닉 목록에서 빠져
있었다. 코퍼스에 **186회** 등장한다.

### 2-8. `firstTonic` 재평가 — 통념이 뒤집힌 사례

**정답 라벨로 특징을 검정**한 결과가 코드 주석의 통념을 뒤집었다.

각 곡의 정답 키와 그 나란한조를 짝지어, 후보 특징의 "정답에서만 참 / 나란한조에서만 참"
빈도를 셌다(1460곡):

| 특징 | 정답만 : 나란한조만 | 판별력 | 발동률 |
|---|---|---|---|
| **첫 코드가 토닉** | 931 : 50 | **95%** | 67% |
| 토닉이 곡 후반부 등장 | 868 : 47 | 95% | 63% |
| 마지막 마디에 토닉 | 584 : 13 | **98%** | 41% |
| V7→토닉 해결 | 784 : 40 | 95% | 56% |
| 마지막 코드가 토닉 | 453 : 11 | 98% | 32% |

**"첫 코드가 토닉"이 최강 판별자인데 가중치는 6점(최저)** 이었다. 코드 주석엔 *"약한 보조 증거"*
라고 적혀 있었다.

낮게 잡힌 데는 이유가 있었다 — 첫 코드가 ii인 곡(Tea For Two의 `Bbm7`)에서 그 ii를 밀어올린다.
그래서 **ii로 기능하는 첫 코드만 제외**하니 6점 → 20점으로 안전하게 올릴 수 있었고, 홀·짝 양쪽이
함께 상승했다. **단조가 77.7% → 81.5%** 로 뛴 게 이 덕분이다.

## 3. 기각한 실험 8건 (같은 실수를 반복하지 않기 위해)

| 실험 | 결과 | 왜 실패했나 |
|---|---|---|
| **가중치 좌표하강 튜닝** | **과적합** | 튜닝셋 84.25→86.16%, **검증셋 84.25→84.25%**(0). 개별 가중치를 하나씩 재도 검증셋 개선 0 |
| 세컨더리 도미넌트의 ii를 설명으로 인정 | 83.4% | 오답 키도 똑같이 사면돼 설명력의 판별력이 무뎌짐 |
| 정격종지(V7→I) 가점 | 83.6%↓ | 토닉화된 ii도 자기 V7→ii를 가져 오답을 같이 밀어올림 |
| 종지를 '마지막 마디 안 어디든'으로 완화 | 84.0% | 나란한조만 보면 **엄격히 우월**(정밀도 98% 동일, 발동률 32%→41%)한데, 전체로는 다른 혼동에서 오답 키도 발동시켜 손해 |
| 프레이즈머리(1·9·17·25마디) 토닉 가점 | 전 구간 하락 | 재즈에선 ii가 프레이즈를 시작하는 일이 잦음 |
| 전조 보정(8마디 구획 중 최악 하나 제외) | 83.4% | — |
| 근음 전용 프로파일 추가 | 변화 0 | 구성음 프로파일과 정보가 겹침 |
| 케이던스 '개수'에서도 피벗 제외 | 변화 0 | 이득 없는 복잡도 |

### 배운 것

1. **가중치 조정은 이미 한계**다. 검증셋 개선이 0이라는 건 현재 신호 조합의 정보를 다 쓰고
   있다는 뜻이다. 더 올리려면 가중치가 아니라 **새로운 신호**가 필요하다.
2. **나란한조 쌍에서 좋은 특징이 전체에서도 좋으리란 보장이 없다.** 특정 혼동을 겨냥한 특징은
   다른 혼동에서 오답 키도 함께 발동시킬 수 있다(→ 반드시 전체 벤치마크로 검증).
3. 재즈에서 **ii는 거의 모든 곳에서 정답을 방해한다** — 프레이즈 시작, 종지, 체류 시간, 첫 코드.
   대응은 일관되게 "ii로 **기능**하는지"를 보고 제외하는 것이었다.

## 4. 방법론 — 이번에 자리잡은 작업 방식

### 4-1. 벤치마크 먼저

`scripts/keySuggestBenchmark.ts` — 1460곡을 10초에 채점. 이게 있어야 "가설 → 측정" 루프가 돈다.

```bash
npx tsx scripts/keySuggestBenchmark.ts            # 요약
npx tsx scripts/keySuggestBenchmark.ts --misses   # 오답 전체 목록
```

### 4-2. 오답을 점수 항목별로 분해

"어느 항목이 오답을 만들었는가"를 평균 기여도로 재면 **단독 원인**이 드러난다.
초기엔 `마지막 케이던스` 가 +18.3점으로 압도적이었고, 그걸 고치자 지금은 어느 항목도
지배적이지 않다(설명력 8.4 / 종지 6.9 / 마지막코드 6.8).

### 4-3. 정답 라벨로 특징을 검정 (핵심)

추측으로 특징을 고르지 말 것. 정답 키와 혼동 대상(나란한조 등)을 짝지어
**"정답에서만 참 / 혼동에서만 참"** 빈도를 세면 판별력이 바로 나온다. `firstTonic` 발견이
여기서 나왔다.

### 4-4. 반드시 홀드아웃

같은 데이터로 튜닝하고 같은 데이터로 자랑하면 안 된다. 곡을 홀·짝으로 갈라
**튜닝하지 않은 절반에서도 오르는지** 확인한다. 이번에 가중치 튜닝이 가짜였음을 이걸로 잡았다.

### 4-5. 회귀 테스트로 잠그기

`src/components/leadsheet/__tests__/keySuggest.test.ts` — 주석에 "실측"으로 기록돼 있던 곡을
테스트로 고정했다. 한 곡을 고치다 다른 곡을 깨는 걸 막는다.

- Tea For Two(Ab) · 리듬 체인지(B♭) · All of Me(C) · F 블루스(F) · "이미 맞으면 침묵"

## 6. 앞으로 — 우선순위별 제안

### 6-1. 지금 바로 할 만한 것 (저비용·효과 확실)

1. **오탐률 측정** — 지금 지표(1순위 적중률)는 "모델이 얼마나 맞히나"이지 **"사용자에게 틀린
   알림이 얼마나 뜨나"** 가 아니다. 실제 UI는 `SUGGEST_MARGIN`(12점)과 "현재 키가 스스로
   설득력 있으면 침묵" 규칙이 있어 오탐률은 15.5%보다 훨씬 낮다. **이게 사용자 체감에 가까운
   지표**이므로 따로 재고, 그 값으로 `SUGGEST_MARGIN` 을 조정하는 게 정확도 1%p보다 가치 있다.
2. **화성 분석 전반 재검증** — 2-1의 정규화 버그는 조성 추천만의 문제가 아니었다. m 표기 차트의
   도수 배지·다이아토닉 판정·ii-V-I 탐지가 전부 영향권이었으므로, 화면에서 눈으로 확인.

### 6-2. 다음 단계 (중간 비용)

3. **곡 중간 전조 지원** — 지금은 곡 전체를 한 개 키로 본다. 브리지가 다른 키인 곡이 많고
   (Tea For Two도 브리지가 C), 이게 극단 오답의 주원인이다. 단순히 "구획 하나 제외"는 실패했으니
   (§3), **구간별 키를 각각 추정해 표시**하는 기능으로 접근하는 게 맞다. 사용자에게도 더 유용하다.
4. **정답 라벨 검정을 다른 혼동으로 확대** — 이번엔 나란한조만 했다. ii·IV·V·동주조 각각에 대해
   같은 분석을 돌리면 `firstTonic` 같은 발견이 더 나올 수 있다.

### 6-3. 큰 방향 (고비용)

5. **혼동 유형별 2단계 판정** — 단일 선형 점수로는 "나란한조엔 좋은데 ii엔 나쁜" 특징을 담을 수
   없다는 게 이번에 반복 확인됐다. 1차로 후보 2~3개를 좁힌 뒤, **그 쌍에 특화된 판별자**로
   결선을 치르는 구조가 자연스럽다.
6. **학습 기반** — 코퍼스에 1460곡 라벨이 있으니 로지스틱 회귀 정도는 바로 학습 가능하다. 다만
   ①현재 규칙 기반의 설명 가능성(사용자에게 "왜 이 키인지" 근거를 보여준다)을 잃고 ②홀드아웃
   결과로 보아 현재 특징 집합의 정보량이 이미 소진돼 큰 이득은 어려워 보인다. **새 특징을 먼저
   찾는 게 순서**다.

### 6-4. 필요한 것

- **정답 라벨의 신뢰도 확인** — iReal Pro의 키 표기 자체가 틀린 곡이 섞여 있을 수 있다. 극단
  오답 상위 20곡을 사람이 직접 보면, 남은 226곡 중 실제로 우리가 틀린 게 몇 곡인지 알 수 있다.
  **정확도 상한을 아는 것**이 앞으로의 투자 판단에 필요하다.
- **평가 코퍼스 확대** — 현재 iReal Pro 1460곡 단일 출처. 다른 출처가 있으면 일반화 검증이 는다.
