1. 제품 개요

Jazzify는 재즈 연주자·학습자를 위한 코드차트/리드시트 분석 + AI 화성학 튜터 + 백킹트랙 연습 통합 플랫폼이다.

핵심 가치내용
분석1,460곡 표준 + 사용자 차트를 ii-V-I·세컨더리 도미넌트·모달 인터체인지로 자동 분석·시각화
AI 튜터RAG 채팅으로 출처(유튜브 딥링크) 달린 답변 + DB 릭 추천
연습풀밴드 자동 반주(콤핑+워킹베이스+드럼, 13장르), 12키 릭 연습, 구간 루프
자료화OMR로 이미지 악보 디지털화, 릭/솔로 DB(WJazzD 8,000+) 검색

플랫폼: 웹(데스크톱/태블릿) + iOS 네이티브(Capacitor) · HashRouter SPA

7. 비기능 요구사항 (NFR)

7.1 보안

  • 시크릿: VITE_는 공개 가능 값 전용. API 키·토큰은 백엔드 보관 필수 (현 위반: C1).
  • 인증: JWT(단기 access, localStorage) + HTTP-only refresh 쿠키 + RTR(재사용 감지 무효화) + 멀티탭 Web Locks.
  • 계정 격리: 로그인/로그아웃 시 사용자범위 캐시 8종·chartEdit prefix·IndexedDB OMR 이미지 정리.
  • CSP: 외부 스크립트 차단(youtube만)·frame/object 제한 메타. SRI·폰트 셀프호스팅 잔존.
  • 에러 노출: 사용자에겐 message만, detail은 dev 콘솔만.
  • 개선 권고: access token 메모리/httpOnly화, Anthropic 호출 백엔드 일원화, npm audit 주기 점검.

7.2 성능

  • 코드 스플리팅: VexFlow/OSMD(~1.1MB)를 차트/악보 페이지에만 lazy 로드.
  • 사운드폰트 캐시: smplr 샘플 IndexedDB 캐시.
  • 재생 정확도: 백킹은 Web Audio lookahead(200ms). 에디터/12키는 setTimeout 기반(§8 R8 공유훅 단일화).
  • OMR 비동기: 폴링 + in-flight dedup으로 중복 POST 방지.

B. 백엔드 요구사항 (Backend Requirements)

프론트엔드에서 해결 불가 — 별도 백엔드(Spring, jazzify.p-e.kr) 또는 인프라(프록시) 수정이 필요한 항목을 발견 순으로 누적한다. 각 항목은 프론트 측 완화(있으면)와 백엔드 조치를 함께 적는다.

BR-1. AI 채팅 응답이 긴 답변에서 중간에 끊김  미해결 HIGH BE RAG LLM

항목내용
증상 RAG 채팅(POST /v1/chat/global/stream, useRag=true)에서 긴 화성 분석 답변이 문장 중간에 멈춘다. 실제 사례: "E-7은 다이아토닉 iii," 에서 종료.
연쇄 영향 코드 차트(```chart 펜스 블록)는 보통 답변 후반/끝에 나오므로, 응답이 먼저 끊기면 차트 JSON 자체가 전송되지 않는다 → 차트 카드 미출력. (즉 "차트 안 나옴" 버그의 상당수가 이 끊김의 2차 증상.)
원인 (프론트 아님) 프론트 스트림 파서는 reader.read() 가 done 될 때까지 정상 수신하며, 폴백 Claude 경로(api/claude.ts)는 max_tokens: 16384 로 넉넉하다. 끊김은 Spring 백엔드 스트림 경로에서 발생.
의심 ① Spring AI Anthropic ChatClient의 max-tokens 가 작게(기본 1024 / 4096) 설정되어 긴 답변이 토큰 한도에서 잘림.
의심 ② 스트림 엔드포인트 앞단 프록시(cloudflared / nginx)의 idle·응답 타임아웃 → 긴 SSE 스트림 도중 연결 종료.
백엔드 조치 ① spring.ai.anthropic.chat.options.max-tokens ≥ 8192 로 상향.
② nginx proxy_read_timeout / cloudflared 스트리밍 타임아웃을 답변 생성 시간 이상으로 상향.
프론트 완화 (적용됨) ChatMessage.tsx 의 CHART_RE 정규식을 관대화 — ```chart {…}``` 한 줄 포맷·닫는 펜스 줄바꿈 변형도 인식. 차트 블록이 응답 앞부분에 완결된 경우는 그려진다. 단 응답이 차트 도착 전에 끊기면 복구 불가 (BR-1 백엔드 조치 필요).

BR-2. 차트 공유용 토큰 기반 공개 엔드포인트 부재  미해결 MEDIUM BE

항목내용
증상 공유(F3.16 코드차트 · F4.11 악보)가 프론트 전용 v1 으로만 구현됨 — 차트/악보 전체를 URL 해시(/v?d=<base64url>)에 인코딩해 링크를 만든다. 백엔드 공유 리소스가 없음.
🔴 선결 조건 (차단) 프론트 전용 공유는 링크를 열 공개 웹페이지가 실제 배포돼 있어야 동작한다. 현재 SPA가 공개 웹(jazzify.app)에 미배포 → 링크를 외부인에게 보내면 안 열린다. 즉 공유 기능은 코드 완성·검증됐으나 웹 배포 전까지 외부 실사용 불가.
연쇄 영향 ① 차트/악보가 크면 URL 길이가 폭증(특히 악보는 음표 수가 많아 더 길어짐 — 일부 메신저가 링크 절단 가능, v1 용인 위험). ② 공유 후 원본 수정이 링크에 반영되지 않음(스냅샷). ③ 조회수·만료·폐기 불가. ④ 악보(F4.11)는 보기 전용 — 원시 음표로 SheetProject를 만드는 백엔드 경로가 없어 "복제" 미지원.
백엔드 조치 ① POST /v1/chord-projects/{publicId}/share → 추측 불가 토큰 발급(멱등, 이미 있으면 재사용) + { shareToken, shareUrl } 반환.
